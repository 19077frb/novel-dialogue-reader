# 性能分析与优化记录

## 范围和测量方法

2026-10-01 检查了书库、导入/删除、正文/目录/标注、人物识别与人物表、单章/批量处理、任务进度、人工更正、恢复、导出、模型配置及前端渲染路径。对 13 条主要本地服务路径做了优化前后测量；不是所有功能都做了端到端负载测试。

基线为 `d292db9` 的实现。Windows 10、Python 3.12.9、SQLite，本机隔离合成数据：50 本书，其中一本有 100 章、2,000 条对白、60 名人物、100 个场景、300 个分组、2,000 条标注、2,000 条待确认原因记录、200 个任务、2,000 次调用记录。进度样本为 40 个窗口、1,000 次尝试。未读取或修改真实书库，未调用付费模型。

每项先预热，再采样三次取中位数；内存单独使用 `tracemalloc` 测量 Python 分配峰值，CPU 热点单独使用 `cProfile`，避免把重跟踪开销混入计时。计时保留轻量 SQL/ORM 计数器，两次测量使用同一口径。SQL 次数包括服务入口装配书籍/版本的读取；它不是单个 HTTP 请求的完整开销。内存不是进程 RSS，也不包括 SQLite 原生缓存。硬件详细型号在受限环境中无法读取，未据此推算吞吐量。

### CPU 与内存热点

| 维度 | 优化前 | 优化后及仍有的成本 |
| --- | --- | --- |
| 导出 CPU（独立 cProfile） | 4,000 段逐段扫描所有标注，`_slices` 累计约 0.970 s | 先建区间索引，再仅切分相交标注；完整跟踪约 1.292 s → 0.284 s。该数据含跟踪开销，不等同于上表计时 |
| 进度内存/重复读取 | 同一批尝试重复装配三次完整记录，含响应/提示等无关字段 | 一次读取窗口、用量、状态、错误码，再复用统计；ORM 装配行数 3,041 → 43 |
| 统计内存/冗余 | 为计数装配候选 JSON；用量装配任务与完整尝试对象 | 待确认统计仅返回聚合值；用量只读取统计所需字段；用量仍为 O(历史尝试数) |
| 章节投影内存/冗余 | 读取全书完整场景、分组和人物对象 | 只读相交场景；跨章节色板仍读全书分组的必要列，ORM 行数 502 → 43 |
| 全书导出内存 | 所有结果都需保留，并反复查询章节节点 | 节点每批 500 行流式读取；渲染结果和冻结投影仍与全书大小成正比，不是恒定内存导出 |

## 功能逐项审查与处理

| 功能 | 数据库/CPU 路径与本轮处理 | 保持的规则或限制 |
| --- | --- | --- |
| 书架、书籍详情 | 活跃版本一次批量取回，书架避免 N+1；时间/ID 联合游标与索引 | 按创建时间、ID 排序；旧 ID 游标在对应记录存在时仍兼容 |
| TXT/EPUB 导入 | 章节批量 flush；引语归章使用二分定位，异常重叠章节回退原扫描；清理旧引语批量检查标注 | 不删有标注的旧引语；解析、安全限额、码点映射和回导恢复不变。整本解析仍占内存 |
| 删除书籍 | 已有 0012 外键引用索引和按书籍删除；保留原实现 | `BEGIN IMMEDIATE`、活动任务保护、文件回收与失败恢复，不为速度绕过外键或事务 |
| 目录、正文、资源、候选详情 | 目录继续直接读 `dialogue_processed`；正文严格按章节过滤；详情只取所属章节 | 不扫历史任务。零长度插图章节不会混入邻章；同码点节点使用完整排序游标，不再循环分页 |
| 初读/重读标注与颜色 | 范围过滤下推 SQL；全书色板读取必要列；颜色分配用单调空位指针 | 人物跨场景颜色稳定、预留颜色、初读身份还原/隐藏、描述选择、人工锁定不变；色板仍为 O(全书分组数) |
| 预览、窗口选择、Token 估算 | 缓存冷加载只取必要列；窗口划分缓存引语 Token、Gap 前缀成本；证据选择只传窗口目标引语 | 不截断目标、不减少证据策略。窗口 ID、依赖哈希、预算及初读范围经原实现对比验证 |
| 人物发现与确认 | 候选匹配复用本次读取的人物表，新增人物及时加入；名单按 ID 批量取回 | 保留原匹配优先级、名单顺序、缺失 ID 跳过和人工姓名/描述保护 |
| 人物表编辑/合并 | 只取未关联分组；同步仅查询目标/来源分组；仅修改确有变化的未完成任务检查点 | 更新引用仍原子完成。章节名单是 JSON 快照，仍需检查全部章节名单，不引入不可靠 JSON 字符串匹配 |
| 单章/批量任务与进度 | 进度读取必要列一次，重用次数与用量结果；任务查找增加复合索引 | 不改变人物识别串行依赖、对白并发限制、停止、额度刷新或未知用量语义；未增加网络并发 |
| 用量、重试、恢复 | 全书用量只读状态、用量及模型快照；恢复路径保留 | 仍按每次尝试自己的模型归属，未知不能当零；恢复要读必要完整快照，不能随意删历史 |
| 待确认队列/详情 | 列表关联 Quote/Gap 直接切原文；SQL 按状态/原因及不同目标聚合 | “原因记录”和“不同对话”分别计数；一个目标的多个原因不丢失，版本/候选/原文保持一致 |
| 人工更正、撤销、失效 | 下游范围下推 SQL；批量预取已有过期记录并集中 flush；对白已存场景归属优先 | 不覆盖锁定项、不删除历史、已解决项可重开。独立处理留下重叠开放场景时，不再依赖索引返回顺序误改归属 |
| HTML/EPUB 导出与校验/回导 | 选中章节 SQL 过滤；两次读取章节/节点；区间索引避免逐段扫全书标注 | 渲染仍只读冻结投影；样式、章节、资源、可见标注、已处理状态和内部校验不变，零模型调用 |
| 模型配置、凭据、健康检查 | 记录规模小，未新增缓存或弱化检查 | 凭据不落日志/性能夹具；健康检查继续真实检查迁移状态，不伪造就绪 |
| 阅读与任务界面 | 阅读正文区间索引按输入引用缓存，给段落仅传相交候选/标注 | 嵌套、同位置优先顺序、Unicode、ruby、鼠标操作保持不变。已存在的刷新合并、进度独立刷新和有限重试不变 |

## 数据库迁移与安全边界

`0013_query_access_indexes` 新增 11 个复合索引，覆盖创建时间分页、章节节点、版本/章节引语范围、Gap/场景范围、任务版本/状态/请求摘要、标注场景/依赖查询。模型定义同步，不增加或删除业务数据列。升级测试验证已有记录保留，并检查索引定义及 SQLite `EXPLAIN QUERY PLAN` 的使用。

升级前按 README 备份 `data/`，停止旧服务后再启动 `start.bat`；脚本会执行迁移。创建索引会扫描已有表、增加磁盘占用和后续写入维护成本，首次启动可能较慢。本轮没有对真实数据库执行迁移。

SQLite 保持 WAL、外键与 5 秒 busy timeout。它仍只有一个写者；提高模型并发不能提高数据库写并发。没有降低持久化保证、缩短到破坏原子性的事务、缓存可变标注投影或删除调用/更正历史。模型落库仍有逐条版本与历史操作，未声称其延迟已经消除。

## 后续建议（尚未实现）

1. 历史尝试达到数万以上时，测量用量统计与轮询尾延迟，再考虑带一致性校验的增量用量表；必须覆盖未知结果、恢复及模型切换，不可简单累计后丢弃明细。
2. 超长书导出仍受冻结投影和结果内存限制，下一步可考虑流式写产物，但需要保持 EPUB 恢复清单及校验内容一致。
3. 人物合并若成为高频重操作，可把章节人物 JSON 的引用另建索引关系表；这涉及数据迁移，当前未实现。
4. 真实批量处理期间的 HTTP p95/p99、SQLite 锁等待、浏览器帧耗时、真实 EPUB 压缩和模型请求延迟需要独立负载测量。本报告是本地合成热路径数据，不保证每本书都达到相同倍数。
