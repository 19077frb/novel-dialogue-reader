# 0023 启动交付与升级策略

日期：2026-09-28 · 状态：已采纳（T19）

## 问题

T19 要让「用户自己就能启动并使用」，还要说明数据与版本升级、示例配置，并在全新数据目录上验证。
需要决定：开发与生产怎么启动（是否同源）、迁移是否自动执行、示例配置放什么（不能有密钥）、
升级时如何保证原书籍与人工确认不丢，以及最终该用什么口径对外描述交付状态。

## 选择

1. **两种启动方式，职责分开**：
   - 开发：`scripts/dev.ps1`（后端 8765 + Vite 5173，`/api` 走代理），改代码即热更新；
   - 生产/自用：`scripts/serve.ps1`（迁移 → `npm run build` → **单端口 127.0.0.1:8765 同源提供 API 与页面**）。
2. **同源静态服务由后端实现**（`NDR_STATIC_DIR`）：把 `frontend/dist` 挂在 `/`，未知的非 API 路径回退到
   `index.html` 交给前端路由；`/api/**` 永远是 JSON 契约（未知路径仍是契约 404），静态路径解析限制在
   构建目录内（`..` 之类不读目录外文件）。单端口部署不需要 CORS，也不额外暴露端口。
3. **迁移保持显式**：应用默认不自动迁移（避免隐式改用户数据），`dev.ps1`/`serve.ps1` 显式执行
   `alembic upgrade head`，`NDR_AUTO_MIGRATE=1` 才在启动时迁移。迁移只追加、可重复执行。
4. **升级以「备份 → 升级 → 校验 →（必要时）整目录回滚」为准**：README 写清步骤；不用手工改表、
   不用删库重建；新增自动化升级测试证明「导入的书 + `user_locked` 人工确认 + 标注历史 + 待确认队列」
   在重跑/升级迁移后原样保留（`test_upgrade_preserves_data.py`，并保留原有 `0001 → head` 数据保留测试）。
5. **示例配置不含密钥**：`.env.example` 列出全部 `NDR_*` 开关（数据目录、端口、CORS、凭据后端、
   模型超时与限流退避、导入/EPUB 限制），密钥只从界面填写并由后端写系统凭据库/会话内存；
   `.env` 已被 `.gitignore` 忽略。
6. **离线演示要标注**：`serve.ps1 -AllowFakeProvider` 只用于离线走查，脚本会打印警告，
   界面/报告都标注「测试用适配器」，绝不用它冒充真实能力。
7. **对外口径**：**工程交付完成，真实验证待完成**。没有真实凭据、网络与人工样本时，只写
   「实现与离线验证通过、live/quality 未验证」，不写「产品已通过验收」。

## 被放弃的方案

- **只支持开发模式**：用户要开两个进程、记住两个端口，不算「可自行启动使用」。
- **把前端构建产物打包进 Python 包/复制进数据目录**：会把构建产物与用户数据混在一起，升级与备份更复杂。
- **启动时无条件自动迁移**：可能在用户不知情时改数据结构，且失败后难回滚。
- **示例配置里放一个占位 `API_KEY=`**：容易被误填并提交；密钥只走界面与凭据库。
- **用「导入→导出」的离线走查宣称真实联调通过**：走查用的是假提供方，只能证明链路可用。

## 验证

- 全新数据目录 + `scripts/serve.ps1 -SkipBuild -AllowFakeProvider`：迁移 `0001`～`0005` 全部执行；
  `GET /` 200（前端构建产物）、`GET /library` 200（深链接回退）、`GET /api/health` 200（`READY`/`0005`）、
  `GET /api/unknown` 404 契约错误。
- 同一实例从零走查：导入原创 TXT（97 码点/1 章/7 节点）→ 任务 `COMPLETED`（`calls=1`）→ 人工确认
  （标注版本 1→2）→ 投影 5 项/图例 `S1` → 导出 HTML 2494 B（无 `http`/无 `<script>`/含 `〔S1〕`）与
  EPUB 2780 B（`PK` + `mimetype`），下载件离线可读。
- 自动化：`pytest backend/tests` → **376 passed**（新增 `test_static_site.py` 2 项、`test_upgrade_preserves_data.py` 1 项）；
  `ruff` 全绿；`scripts/verify.ps1` 退出码 0；全量 E2E **33 passed**。
- **仍未验证（BLOCKED）**：真实提供方端到端试用、真实作品效果评测（B1–B4 全 `NOT_RUN`）、
  EPUBCheck 标准检查（无 jar）、≥2 款独立阅读器试读（本机无阅读器且不能联网安装）。

## 后果

- 用户按 README 即可：`scripts/dev.ps1` 开发、`scripts/serve.ps1` 单端口自用；升级有备份/迁移/校验/回滚步骤。
- 后续拿到凭据/网络/阅读器后按 `docs/verification-report.md` 的索引补齐 live 与 quality 结论，
  并把账本的 Live/Quality 列从 BLOCKED 改为实际结果。
