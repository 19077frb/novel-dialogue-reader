本次读取本地 SQLite、规范化原文、模型结果缓存与源码，并将数据库复制到内存进行流程重建。没有调用收费 API、读取密钥、修改原书/标注/配置/缓存。现有缓存是解析后的结果，不是完整 HTTP 响应；提示词复现基于当前源码与任务参数，不冒充当时保存的原始请求日志。

## 3. 主要原因与补救

### P0-A：模型看不到 ID 与原文的对应关系

源码：backend/src/ndr/scenes/runner.py:62，llm/prompts/labeling.py。

_messages_for 只把 fragment.text 传入正文；目标、Gap、证据的 ID 另列数组，没有逐段对应的位置、类型和 ID。离线重建两个窗口，每个有 46 个目标，正文数据块包含的目标 ID 数量均为 0。模型自行认出真正对白后，容易把结果按顺序填进包含强调词/注释的目标数组，造成错位。

片段本身已按原文位置排序，因此不是“把叙述全挪到了最后”。问题是序列化时丢掉了 ID 对应关系；按换行拼接还会把叙述内嵌引语变成独立一行，削弱其版面线索。

修复：使用请求内短引用 Q1/G1/P1，显式发送 id、type、text，保留顺序及段落/内嵌关系，输出由程序映射回稳定 ID。区分目标与只读上下文；重复出现的“嗯”不能靠字符串匹配定位；省略段落须标注位置和原因。

### P0-B：人物描述与合法引用不对应；临时引用跨窗口碰撞

源码：scenes/runner.py:70，scenes/state.py:118，speakers/groups.py:41。

摘要是 S1:义妹、S2:我、S3:老爸；允许返回的值却是 UUID 和 new1/new2/new3，S1/S2/S3 不在合法列表中，也没有显式的描述→合法引用映射，只能让模型猜列表顺序。

另外，register_temp_speaker 对 new1 先查旧状态；新窗口声明同名新人时会返回旧人物，忽略新描述。纯内存复现 returned_slot is old_slot 为 True。最新成功第二窗口没有 new_speakers 声明，不能把这一碰撞断言为本次全部错误的直接原因；它是确定存在的后续风险。

修复：发送人物表，明确合法短引用、语义描述、可靠发言锚点与稳定分组映射。NEW 作用域限定为请求和场景；请求结束销毁临时别名，只携带稳定引用。不同请求的 N1 不得自动等同。同场景匿名显示不等于内部不能记录“叙述者/父亲/刚入场女性”等语义。

### P0-C：ACCEPTED 不是已验证的正确归属

源码：scenes/acceptance.py:48、:67，llm/validation.py。

模型自报 basis=DIRECT 即直接 ACCEPTED；证据校验主要检查引用存在，不检查语义是否支持归属。最新 92 条均只引用自身 quote_id 作为证据，仍全部接受。自我介绍可能允许自引证据，但不能把这种写法视为所有对白都可靠。

另一个确定问题：kind=unknown 由于“不是 speech”直接走 ACCEPTED。历史 Pro 全范围任务报告的 47 accepted 中，46 条实际是 kind=unknown，只有另 1 条是 speech/DIRECT。不能理解为识别对了 47 条。

修复：类型判断、说话人可靠性和待确认分开计数；unknown 类型进入未知队列。区分明确发言归属、自我介绍、语义承接和风格猜测；增加元信息发言、身份冲突等异常检查。无法确定的语义不伪装成程序已验证；同时通过真实样本校准承接关系，避免把所有省略主语的正常交谈都交给人工。

### P1-D：场景判断没有可靠发挥作用

最新两份有效缓存共 41 项 Gap 决策，全部 CONTINUE，没有 BREAK/UPDATE/UNCERTAIN；92 条标注共用一个场景。原文包含日常对话示例、父子交谈、书店前辈发言、餐厅四人会面、店外两人交谈。

不是每次换地点都必须切场景，但参与关系变化也不应全部视为无变化。Gap 无 ID 对照、提示词缺少边界正反例是已观察到的问题；应先修输入再评判模型能力。

修复：明确四种边界判断的业务含义，给 Gap 左右发言和位置；结构化更新人物进出。保持心理描写不自动切场景、调用窗口不等于场景的原则。尽量一次主要调用联合判断，仅冲突片段额外复核。

## 4. 另外确认的工程风险

### 缓存不覆盖实际动态输入

源码：jobs/scheduler.py:172、:224，context/window_builder.py。

规划未传入动态人物状态；缓存指纹使用片段文本和预生成 dependency_hash，实际请求额外加入当时的 state.prompt_state() 和合法人物引用。离线构造两种状态，实际消息不同，缓存计算结果相同。提供方 endpoint 也没有进入 _cache_key_for。

本次首窗口缓存命中已确认，但没有证据证明这次属于错误复用。修复应对最终规范化语义请求、端点/协议/模型/参数、人物及人工锁定状态、提示词/契约/接受策略版本取指纹；密钥不进入日志或指纹。升级协议版本隔离旧缓存，保留历史实验。

### token 结构开销大，费用可能低估

同一启发式估算器重建：两个窗口正文约 2460/2488 tokens，完整消息约 5625/5506 tokens（第二项为空人物状态基线），正文以外约 3165/3018 tokens；计划只固定预留提示词 900。上述为本地估算，不是提供方账单。重复长 ID、完整 JSON Schema 和多个 ID 列表开销明显。

最新任务成功调用记录 6992 输入 + 5082 输出 tokens；还有一次格式失败调用 usage_json=NULL。因此 12074 只是已知部分，不是两次调用完整用量。jobs/service.py:324 的预算汇总不把 FAILED 且缺 usage 的尝试计入 unknown_runs；适配器在解析失败之前也没有保全 usage。

修复：短 ID、紧凑输出、减少重复列表；按最终消息和结果数量估预算。先保存提供方 usage 再解析内容。区分未发出失败和远端已生成但格式错误，后者未知费用也应占用保守预算。不要只靠加大 max_tokens 掩盖格式问题。

## 5. 按顺序执行的补救计划

| 顺序 | 工作 | 验证门槛 |
| --- | --- | --- |
| Q00 | 使用 SQLite 一致性备份（含 WAL）；保存当前结果/版本/配置；扩充并复核诊断样本 | 可独立比较实验，不覆盖阅读数据 |
| Q01 | 修复文本、Gap、人物映射协议；短 ID、段落关系和可靠锚点 | 最终请求中的每个 ID 与文本唯一对应；重复台词、注释、嵌套引用不串位 |
| Q02 | 修复人物临时作用域、接续和实际输入缓存；协议版本升级 | 不同窗口 N1 不误合并；人物状态改变时缓存失效；同语义请求可复用 |
| Q03 | 修复 unknown 接受与统计；类型/证据/冲突检查 | 元信息不被认作可靠对白；全部未知不显示成功识别人；人工锁定保留 |
| Q04 | 修复失败 usage 与最终请求预算；脱敏的请求结构与结果来源 | 格式失败、超时、成功、缓存均可追溯；未知费用不为零；无密钥落盘 |
| Q05 | 同配置 Flash、压缩关闭，独立重跑序幕，对照当前结果 | 衡量类型、归属聚类、场景、可用覆盖率、修正量、总 token，而非只看 ACCEPTED |
| Q06 | 残余难例做局部补上下文，再比较窗口大小、思考开关或 Pro | 公平输入和参考样本、包括所有重试成本；只升级有证据获益的难例 |
| Q07 | 再优化结构开销和长叙述筛选；扩展到未调参章节及导出 | 留出章节仍有效；人工锁定、阅读时点与 EPUB/HTML 投影一致 |

Q01–Q04 是工程修复；Q05–Q07 才能验证真实效果改善。Q01–Q04 已按决策 0026 实现；没有执行付费重跑，也没有替换原结果。

建议先完整核读序幕 92 个候选，再从未调参的后续章节抽取至少 100 个候选作留出测试。覆盖强调词、假想发言、心声、译注、自我介绍、多人场景、人未到声先到、连续同人发言、跨窗口、回忆和心理描写。不能只测试简单两人交替发言。

参考分组使用场景内匿名 ID，允许编号置换。分开衡量类型准确率、人物归属、误合并/误拆分和覆盖率，不能把“非对白分类正确”算作“说话人正确”。11 句样本是诊断起点，不足以宣布质量达标。

## 6. 必须补的回归与验收

1. 最终消息中每个目标/证据引用能定位唯一片段，而不只是检查消息包含 ID。
2. 内嵌引语保持类型线索；重复短句、重叠上下文精确回写。
3. 人物描述与合法引用显式对应，跨窗口保留可靠锚点。
4. 不同请求同名 NEW 不复用旧组，同请求引用同一新人仍归同组。
5. 动态状态、端点、接受策略、人工锁定改变时缓存失效。
6. unknown 类型不 ACCEPTED；DIRECT 枚举不是质量通过条件。
7. 解析失败保存 usage，远端尝试缺 usage 时保守计入预算。
8. 模型输出格式全通过、但违反参考归属时，质量评测必须失败。

既有交付文件中多项真实质量验证仍标记未完成，功能流程实现不等于达到阅读效果。应把真实样本评测作为修复后的验收门槛。当前证据不支持承诺换模型后的准确率，也不支持计算全书准确率。
