## 启动

### 最简单的方式

在 Windows 资源管理器中双击 `start.bat`。脚本会自动执行数据库迁移、构建前端并打开：

<http://127.0.0.1:8765>

停止服务时双击 `stop.bat`，或在启动窗口中按 `Ctrl+C`。

也可以在 PowerShell 中运行：

```powershell
.\start.bat
```

更换端口：

```powershell
.\start.bat 8800
```

### 单端口启动

```powershell
pwsh -File scripts/serve.ps1
```

常用参数：

```powershell
pwsh -File scripts/serve.ps1 -Port 8800
pwsh -File scripts/serve.ps1 -DataDir D:\novel-dialogue-data
pwsh -File scripts/serve.ps1 -SkipBuild
pwsh -File scripts/serve.ps1 -Stop
```

### 开发模式

开发模式会分别启动后端和 Vite 前端：

```powershell
pwsh -File scripts/dev.ps1
```

- 前端：<http://127.0.0.1:5173>
- 后端：<http://127.0.0.1:8765>
- 健康检查：<http://127.0.0.1:8765/api/health>

停止开发服务：

```powershell
pwsh -File scripts/dev.ps1 -Stop
```

## 首次使用

1. 在书架页面导入 TXT 或 EPUB。
   - EPUB 中常见的 `&nbsp;` 等标准 HTML 字符实体会自动兼容，导入提示会列出涉及的文件。不会修改原 EPUB、执行脚本或加载外部内容；标签错配、未知实体等仍会拒绝导入。
   - 竖排或浮动标题中人为拆成单字的短段落，会结合原书的本地 CSS 整理为连续文字，避免作者名、英文单词一字一行。普通正文、图片与注音仍保留；不保证还原原书的字体、旋转、坐标或全部视觉设计。仅解析包内已登记的样式和内嵌样式，不下载外部 CSS、字体或 `@import`，也不执行脚本。带标注的 EPUB 回导不再重新整理分段，避免改变标注位置。
   - 更新到包含此排版兼容的版本后，若已有环境未同步新依赖，在项目目录运行 `uv sync --project backend --all-groups`，然后重启服务。已经导入的正文不会被自动改写，需重新导入原文件才能采用新的分段规则。
   - EPUB 优先按原书目录划章，而不是每个正文文件各算一章。一个章节可包含多个文件，同一文件中的多章按目录锚点拆分；未列入目录的出版社标志、扉页、续页和插画保留在所属章节，不生成多余的“第 x 节”。合集的卷级目录作为章节名前缀显示，同一位置的卷名与章节链接不重复建章。缺失或无效的目录项会提示，完全没有有效目录时才回退到文件与标题划章。
   - 纯插画章节仍会并入相邻正文，图片与顺序均保留；全书只有图片时保留为一章。带标注的 EPUB 回导保留导出时的章节结构，避免破坏标注匹配。已导入的书籍不会自动重排；重新导入原文件会创建使用新规则的版本，旧版本的数据保留，但不自动迁移旧标注、人物名单或已处理状态到新版本，请保留原书及标注导出备份。
   - EPUB 默认最多 1000 个正文文档、2000 个 ZIP 条目，解压总量最多 200 MiB、单条目最多 32 MiB。长篇合集可通过 `.env` 的 `NDR_MAX_EPUB_SPINE_ITEMS` 调整正文文档上限；显式配置优先于默认值，修改后需重启服务。
2. 打开“模型配置”，填写 API 根地址、模型名称和 API Key，并测试连接。
3. 进入书籍的预览与处理页面，先选择“单章处理”或“批量处理”，页面只展开对应配置。
   - 没有正文文字（仅空白、插图，或仅有与章节名一致的标题）的章节会自动记为已完成，不调用人物识别或对白模型，不消耗 Token。新导入时即可识别；服务启动时也会检查并补齐旧书中这类短章节的完成状态，无需重新导入或逐章重试。人物分析开始前仍会本地检查，强制重做也不会调用模型。标题-only 必须有对应的标题节点，不能仅因章节名含“插图”或没有对白而跳过；有正文但没有识别出人物的章节不按此规则标记完成，以免掩盖模型错误。正文文件缺失时保留错误，不会误标完成。手动指定的完成标记不会被启动检查覆盖。
4. 单章处理时，选择模型和最大并发窗口数，确认或修改章节人物表并选择本章主视角人物，然后从预览出的窗口中勾选要处理的窗口。
   从阅读页点击“预览与处理”时，会带入当前正在阅读的章节：单章处理默认选中该章，批量处理的开始章节也默认选中该章。可手动调整；直接进入处理页或传入失效章节时默认从第一章开始，不会自动启动模型任务。
   点击“去阅读”会返回进入处理页前的阅读章节，即使临时改为处理其它章也不会丢失原阅读章节；直接进入处理页时则返回当前选中的单章。明确跳转章节优先于最后阅读位置，失效或外书章节链接会回退到本书最后阅读位置（没有有效记录则第一章）。
5. 需要连续处理时，选择开始和结束章节，检查模型、每窗口复核数、Token 上限和最大并发任务数；查看 Token 预估后再启动。单章和批量共享同一套记忆配置。
6. 处理期间可以进入阅读页继续阅读；目录会区分排队中、正在识别人物、人物已确认并正在处理对白 `x/y`、已完成以及失败/已停止。
7. 在阅读页检查颜色和人物标签；通过待确认队列修正不确定结果。
8. 从阅读页或预览页导出 EPUB 或 HTML。

### 删除书籍

- 每本书的书架卡片都有“删除”按钮，并显示导入时间，方便区分同名书籍。确认框会列出书名、导入时间和书籍 ID；只删除所选的这一册。
- 删除会清理该书的版本、阅读进度、人物、标注、待确认队列、人工更正和任务/导出记录，应用内无法撤销。书籍源文件、正文资源和导出文件移入 `data/trash/<书籍ID>-<随机ID>/`，不会删除用户原始文件所在目录；回收区不包含数据库记录，不能直接撤销删除，可取出源文件或此前导出的 EPUB 重新导入。
- 本书批量处理或模型任务仍在运行/排队时不能删除；先停止并等待任务结束。删除后可重新导入。模型配置、其他同名书籍和共享结果缓存不受影响。
- 删除期间该卡片暂不能进入阅读；后台先清理数据库，再将文件移入回收区。启动时的数据库迁移会补齐删除所需的外键索引，避免长篇书籍删除时反复全表扫描。更新后请重启服务以执行迁移。

### 单章窗口处理

“单章窗口任务进度”中的“查看任务”会自动滚动并聚焦到下方对应窗口详情，显示状态、耗时、调用次数、失败原因和恢复操作，不会重新调用模型。详情标题注明窗口编号；手动选中的任务不会被后续窗口派发或整批结束覆盖。重复点击当前任务也会重新定位；开始新一轮处理时清除上轮的手动选择。

- 选择章节后，页面会自动列出本章的处理窗口，包括窗口序号、目标对白数、预估 token 和正文预览；也可手动刷新估算。
- 窗口显示已完成、失败或未完成，以及已保存对白数。默认只选未完成窗口，可一键只选失败窗口，也可全选包含已完成窗口（相同输入仍可复用缓存）；没有选中任何窗口时不能开始处理。状态来自数据库，刷新后仍可查看。
- 如果旧任务的所有窗口均已保存标注，但目录尚未标为完成，可点击“同步章节完成状态（不调用模型）”修正，不必重跑模型。
- 选择“单章处理”和章节后，“选择处理范围”区域会自动生成窗口预览（不调用模型），显示各窗口的对白数、Token 估算和文本片段。可勾选不连续的多个窗口；只有选中的窗口执行对白归属。窗口预览失败、加载中或未选窗口时不能启动任务，可点击“重新读取”或“重新预览窗口与估算”重试。
- 窗口选择只限制对白归属推理的范围。人物分析始终读取整章，避免只看局部内容而漏掉人物身份。补做窗口与此前成功窗口共同覆盖全章时，会更新整章完成状态；目录不会继续显示旧批量任务的失败。切换章节会重置窗口选择；未手动选择时，窗口状态刷新会自动排除新完成窗口，用户明确勾选的窗口则保留。
- 所选窗口按“最大并发窗口数”并行执行（1–16，设为 1 时保持串行）。输入、输出 token 上限会按各窗口的本地估算比例分配，避免拆成多个任务后把整章上限重复使用多次。
- 并发窗口共享已经确认的整章人物表，但不会依赖其它并发窗口临时产生的场景状态；特别强调跨窗口连续对话时，可将并发数设为 1。
- 单章任务提交后立即显示“单章窗口任务进度”和可切换的任务详情，区分等待派发、排队中、处理中、完成与失败；创建接口返回 `QUEUED` 只表示已排队，不表示失败。一个窗口到达真正终态后才释放并发槽位，全部窗口结束前不能新建任务。窗口失败会保留具体原因；进度读取失败仅重试只读查询，不自动重发模型调用。所选窗口全部成功，且连同此前成功窗口覆盖全章时，标记整章完成。
- 预览与处理只保存一套最终标注，因此不再区分“初读”和“重读”。这两个模式仅在阅读页控制显示方式：初读尽量避免使用后文才能得知的身份信息，重读展示最终确认结果。

### 批量后台处理与 Token 上限

- 单章和批量处理共享模型配置、每窗口复核数、最大并发数及额度数值，修改任一模式都会同步到另一模式。配置保存在当前浏览器的本地存储中，切换页面、刷新、重启服务/浏览器后仍保留，且跨书共用；不保存模型密钥。单章额外的输出 Token 上限也会记忆。默认额度不限。
- 保留现有预算口径：单章表单的输入 Token 上限与批量的本次累计 Token 上限共用数值；单章输出上限仍单独约束输出，批量仍按总用量扣减额度。共享配置不改变正在运行任务的模型、复核数或并发限制；批量运行中的额度调整仍原地生效，并保存为后续处理的额度。
- 章节范围、勾选的窗口、强制重做和运行进度不是记忆配置。模型配置被删除后，会自动选择当前可用的配置；没有配置时提示添加。不同浏览器或不同访问地址的本地存储不共享；清理浏览器数据会重置设置。若浏览器禁止本地存储，配置只能在当前页面会话内保留，关闭后无法保证恢复。
- 默认跳过已处理章节。勾选“强制重做已处理章节”后，所选范围全部纳入 Token 预估，并重新识别人物、重新调用模型处理对白（跳过对白结果缓存）。可用开始/结束章节限定重做范围；人工确认或锁定的标注仍会保留。切换此选项后需要重新估算，再确认启动。
- 人物识别严格按章节顺序执行：第 N 章人物确认成功后，才启动第 N+1 章人物识别，保证后章沿用前章已确认人物。人物任务之间不会并发；已确认章节的对白窗口仍可与下一章人物识别并发，并共享最大并发任务数。
- 某章人物识别或确认失败时，只记录该章失败并跳过其对白，随后继续下一章，沿用此前成功确认的人物。识别结果没有人物（如插图章、空白章）时，显示跳过原因，不作为失败；本章不处理对白，也不标为已完成，后续章节继续。
- 单个章节或窗口失败只标记自身；其他章节和同章未失败的窗口会继续处理。用户主动停止或本次 Token 上限耗尽时才安全停止整批。
- “每个窗口最多复核的待定对白数”是首次有效结果中最多挑选多少条待定对白补充上下文复核，不是失败重试次数；0 表示关闭，显式设置的数量优先于上下文策略默认值。首次有效结果已经保存后，普通复核错误不会删除它或使已完成窗口失败；复核超时因远程结果、计费不明确，会暂停为待核对状态，已保存标注仍保留。所有实际调用均计入用量。
- “校验失败后的重试次数”独立控制对白输出无效时的纠错重发：默认 1 次，可设置 0～5 次，不包含首次调用。例如设为 2，连续无效时最多尝试 3 次；设为 0 则首次失败就停止。单章（包括试运行）、批量、自动处理和阅读中的局部复核共用并记忆这一设置；已启动任务及目录按钮重试沿用启动时设置，修改只影响新任务。自动待定对白复核的每个窗口也受同一重试上限约束；复核最终失败仍保留首次有效标注。重试携带具体校验问题，实际调用均增加用量，停止或剩余额度不足时不继续调用。此配置不控制人物识别，也不改变限流/暂时不可用的服务端有限退避策略；超时、结果未知、鉴权失败不因此自动重发。预估不是最坏情况下所有重试的费用承诺，实际用量以每次调用为准。
- 场景起点只能引用本窗口目标对白。窗口尾部、下一章或重叠上下文仅作为证据，不提前建立没有目标对白的新场景；无法唯一确定的场景或说话人冲突仍由严格校验拒绝，不会自动猜人。
- 批量结束后，可在预览页任务列表点击失败任务的“重试人物识别”或“重试窗口”。对白重试复用已确认人物，只调用所选失败窗口；人物重试成功后继续该章未完成窗口。重试沿用原模型、复核数、并发配置和剩余额度，不清零已用额度、不重复成功窗口。逐窗口重试需等当前批量结束，整章重试见下文。刷新浏览器会清除本次任务列表，可在单章处理中选择未完成窗口恢复。
- 阅读目录中，失败或已停止章节的名称旁显示重试图标，一次补齐本章上次任务中失败或取消的窗口；成功窗口不会重新调用，原来未选择的窗口不会额外加入。已确认人物会复用，人物尚未确认则先重新识别，再继续原任务范围中未完成的窗口。其他章节仍在处理时，本章重试可直接加入同一个队列，共用并发上限与剩余额度，不必等待整批结束。请求结果不明确时会提示检查详情，避免重复调用。预览页任务列表仍保留逐窗口重试；阅读侧栏不再列出单独的窗口重试按钮。
- 排队或执行中章节的名称旁显示取消图标，只取消该章的全部任务，不影响其他章节。不再派发本章排队任务；已提交任务请求暂停，并等待在途请求安全收尾，不能保证远程请求立即停止计费。收尾期间显示“正在取消”并禁用操作，已保存标注和实际消耗保留；收尾完成后可通过重试图标恢复未完成部分。暂停请求失败会显示实际错误，但本章后续派发仍被阻止。任务记录仅在当前浏览器页面会话保留。
- 后续章节会沿用本书前面已经确认的人物，同时仍会分析当前章节中新出现的人物。
- 批量任务运行时可以在应用内切换到阅读页。阅读目录会显示排队、人物识别、对白窗口进度、完成及失败/停止等状态，并用不同颜色区分。
- 普通任务进度只更新进度面板；某个窗口完成时只合并刷新当前正在阅读章节的标注，整章完成时才合并刷新目录。目录直接读取章节保存的 `dialogue_processed` 状态，不会在每次打开时扫描历史任务。
- 书籍、目录、正文等只读请求遇到网络、限流或服务端临时错误时最多自动重试两次；仍失败会显示后端返回的具体错误，并提供“重新读取”。
- 批量启动后，“预览与处理”中的配置会替换为实时进度面板，逐项显示人物识别或对白归属、所属章节、窗口编号以及排队中/处理中/已完成/失败状态。运行期间不能切换处理模式或新建另一项任务。
- 批次结束（含失败或停止）后，页面保留“最近一次批量任务列表”，在“原因 / 错误详情”列查看具体原因，同时恢复批量配置。错误提示提供“查看任务列表”链接；应用内切换页面或处理模式后仍可查看，下一批启动会替换列表。列表仅保存在当前页面会话，刷新或关闭页面会清除。
- 进度面板提供“停止批量处理”：停止后不再派发排队任务，已经发给模型的请求会安全收尾；从阅读页返回时仍可查看并停止当前批次。
- 启动前会先计算预计 token。第一次点击用于查看预估，确认后再次点击才会真正启动。
- Token 上限留空表示不限制。用量接近上限的 80% 时会提示：填写新的上限会直接继续当前批次，不会重新开始，也不会清零已用量；填写 `0` 表示提供方额度已刷新，并从零重新计算本批次额度。
- 设置上限时，系统按启动前估算为并发任务预留额度，并把预留值作为各任务的后端硬上限；所有在途任务的预留之和不会超过批次剩余额度，完成后再按提供方返回的实测用量结算。
- 如果提供方没有返回 token 用量，设置了上限的批量任务会安全停止，避免把未知用量当作零继续消耗。
- “后台”指在当前浏览器会话中切换页面后仍继续处理。批量任务完成前不要刷新、关闭页面或退出应用，否则批量调度不会自动续接。

### 引号修复

- 导入时会检查跨段仍未闭合的 `“`：如果下一处引号是新的 `“`，后端会在原段落末端生成一条虚拟 `”` 修复建议。
- 修复只作用于候选对白扫描和后续标注，不会改写原始文件或规范化正文。
- 独立“书籍预处理”页面会显示原文、虚拟闭合效果和原因；可以用原文光标、逐字/逐标点移动来定位闭合位置，也可以替换字符或停用修复，并保存重扫。
- 重新检测或保存修复点只更新候选引语的边界，不会清除对白归属、人物名单或人工锁定结果。

### 思考模式（可选）

预览与处理页在“选择处理方式”下方统一提供“模型配置与本次思考设置”，将模型选择、思考模式和强度放在同一卡片中；单章和批量共用此配置区，处理范围中不再重复选择模型。对白详情的局部复核也采用相同的合并布局。

阅读时打开对白详情的“局部复核”，也可调整思考模式和强度，查看所选模型默认值；与预览与处理共用模型选择及思考偏好，不另存一套。复核输入额度仍在该面板单独确认。创建任务时固定参数快照，运行期间禁用本面板配置与重复启动；完成或停止后允许重新发起，人工锁定的对白不被覆盖。

模型配置页提供最大输出 Token（`max_tokens`）、随机性（`temperature`）、采样范围（`top_p`）和请求超时（`timeout_seconds`）表单，留空沿用默认值。原始 JSON 为折叠只读展示；编辑常用项不会删除已有提供方专用参数。

模型配置页也提供“默认思考模式”和“默认思考强度”，保存后作为该配置的默认值。选择“模型服务默认（不指定）”会清除对应默认参数，并不代表关闭思考。关闭模式会清除默认强度。在处理页选择“沿用模型配置”时读取这些默认值，并显示当前所选配置的默认设置；明确选择其它值只覆盖本次任务，不改写模型配置。沿用的模式为关闭时，任务也不发送强度。

在“预览与处理”的“模型配置与本次思考设置”中，可随时选择沿用配置、关闭、开启或自适应（发送 `thinking.type`），并选择低/中/高强度（发送 `reasoning_effort`）。必须由所选提供方支持这些参数；不支持时选择“沿用模型配置”。单章、试运行、人物识别及批量共享并记忆设置。关闭思考时忽略强度；任务启动后固定快照，不修改模型配置或运行中的任务，不自动增加输出上限或超时。

```json
{
  "thinking": { "type": "disabled" },
  "max_tokens": 16000,
  "timeout_seconds": 300
}
```

Base URL 应填写 API 根地址，不要包含 `/chat/completions`。模型能力和兼容格式可能变化，请以提供方当前文档为准。

## 通用设置

“自动提前处理章节”默认关闭。开启后，在阅读页按当前章及后 N 章（0–100）自动估算并处理：先依次确认人物，再让对白窗口与下一章人物识别共享并发池。切换阅读章节时会估算新增目标章节并追加到当前队列，不必等上一批全部结束；有空闲并发位置就继续派发。人物识别仍串行，尚未启动的人物任务按章节顺序安排，已经启动的任务不会打断或重排。已完成、已排队和本会话已尝试的章节不会重复加入；向前或向后跳章不会取消已有队列。应用内切换页面不会中断已启动任务，刷新/关闭页面不会恢复调度。自动预估不需要额外确认，开启选项即授权后续模型调用。

模型、思考模式/强度、每窗口复核数、并发数和 Token 上限与手动处理共用设置。追加章节共用当前任务池的并发限制、模型设置和剩余额度，不另建一批或重置用量；自动用量在当前页面会话中按书籍累计。接近上限时提醒，额度不足或模型用量未知时安全停止。阅读侧栏可停止自动处理（停止接收新章节，不再派发排队任务，在途请求收尾），或在没有自动任务运行时“刷新额度并重试”。失败/空人物章节不会无限自动重试；“刷新额度并重试”会清除本会话尝试记录，单项失败重试不会清零额度。手动任务或其他书籍任务运行时自动处理等待；模型、思考和并发配置修改仅作用于下一次新任务池，不改变正在运行或追加的任务。

顶部导航的“通用设置”可调整正文字号、行距、自动续读及阅读页默认候选引语/标注显示；设置自动保存到当前浏览器。显示开关不会调用模型或改变已有标注，自动续读关闭时默认从第一章打开（明确的章节/书签跳转仍优先）。字号与行距不改变导出文件。

“阅读显示”中的“双击目录章节名切换完成状态”默认关闭，开启后立即生效并记住设置。阅读目录中双击未处理章节会标为已完成，双击已完成章节会改为未处理；排队中、处理中、失败或已停止的章节首次双击也标为已完成，再次双击改为未处理。双击不跳转章节；开启此功能后，鼠标单击会稍候以区分双击，键盘激活仍立即阅读。保存期间禁止重复提交，失败会显示具体错误并保留原状态。

这只是完成标记，不删除正文、人物、标注、任务记录或历史用量，也不停止在途模型请求（仍可点章节旁的取消图标）。手动标记保存到书籍，重启、当前后台任务收尾及无正文启动检查都不会覆盖；已完成章节会被后续批量/自动处理跳过。重新开始该章的单章正式处理、批量/自动处理或失败任务重试时，会解除该章手动标记保护并恢复正常进度更新；重做手动完成章节仍需开启强制重做。EPUB 导出和回导会保留手动标记。

## 书籍预处理

导入、删除、导出生成、人物识别及对白任务会显示实际等待时间或完成用时。批量/自动处理与窗口任务有完成进度时，按已完成任务的平均耗时估算剩余时间；模型服务响应速度和任务大小不同，估算会变化，不是保证完成时间。计时只刷新小型时间显示，不会重新读取目录、正文或标注。

正文长度和处理范围以字符表示，标点、换行和单个 Unicode 字符（包括表情、扩展汉字）也计入；范围位置从 0 开始，不含结束位置。界面使用普通阅读用语，任务的内部进度字段可在“任务诊断详情”中查看。

导入新书时先自动检查章节，再自动检查并启用引号修复，不调用模型、不改写原文。TXT 会排除明显的正文式编号标题，并合并紧邻、仅空行相隔的重复序章标题；EPUB 正式章名不会因标点、长度或以“第”开头而被自动合并，仅前一节只含标题的重复序章可保守合并。应用导出的带标注 EPUB 保留章节结构，确保标注和已处理状态能还原；复用已有版本不覆盖用户调整。

导入完成后显示两项修复的数量，可点击“检查预处理结果”。页面先列“章节名与边界修复”，再列“引号修复”；可改名、合并误分章节、重新检查建议，或调整/停用引号修复后重扫。已有书籍也可手动修复目录。

修复只更新目录元数据与章节归属，不改 canonical 原文、对白位置或书签位置。合并无法自动撤销；已有标注、人物名单或完成状态的相邻章节不能合并，只能改名。本书存在运行、排队或可恢复任务时禁止修复；请先处理任务。失效版本或过期标题会拒绝保存，需重新读取目录。

在“预览与处理”中选择“打开预处理”，可检查章节与引号。修复记录默认折叠，展开后可调整并保存；不需要每次处理都进入此页。返回处理或阅读时保留进入前的章节。导入在服务工作线程中解析文件，避免占用阅读请求的主线程；数据库写入期间仍可能短暂等待。

展开修复记录后，可在原文框点击定位或用左右键移动光标；也可用“前移/后移一字”“上一个/下一个标点后”“移到段尾”调整闭合位置。下方即时显示闭合标记，确认后“保存并重扫”；字符位置输入作为高级操作保留。位置计算按 Unicode 字符，emoji 不会被拆成两个位置。

## 阅读进度与书签

- 阅读目录切换与滚动会自动保存最后阅读位置，滚动写入会合并并串行执行；书架显示“最后读到”的章节，重新进入阅读可续到原文段落。保存失败会有限重试并提示，关闭页面前仍未完成的请求不能保证保存。
- 阅读侧栏的“目录 / 书签”为同级标签；目录标签下直接显示章节状态图例和章节列表，不再重复显示“目录”标题。切换到书签可直接查看、跳转、编辑备注或删除，无需离开阅读页，仍保留独立书签页入口。
- 正文每个非空段落提供一个 ☆ 书签按钮（悬停或键盘聚焦显示，触屏直接显示），可收藏章内已加载的段落并填写备注，位置保存为段首。段落内有多句话也只显示一个入口；标题、图片和空段落不提供入口。不调用模型，不改变原文、注音或标注。
- 手动书签可保存多个，允许修改备注和删除；不会随自动阅读进度更新。书签绑定原文版本，版本更换后旧书签保留但不能跳转到新版本；删除书籍会一并删除其书签。
- 续读和书签跳转从章首加载正文并滚动到目标段落，保留本章前文供直接向上阅读，不再提供“查看本章前文”按钮。已有逐句书签的位置和备注保留，跳转时定位到所在段落。长章节仍按分页加载；目标在后续分页中时会自动加载到目标所在页，其余后文按需加载。书签数据目前不随 EPUB 导出/回导迁移。

## 已知限制

- 对白归属取决于文本线索和所选模型，结果仍需要人工复核。
- 无引号对白、复杂嵌套引用和极长章节可能需要手动修正。
- EPUB 的复杂 CSS 不保证完全还原，但正文、章节和本地资源会被保留。
- 再次导入本工具导出的 EPUB 时，会恢复导出时可见的颜色/人物标注以及已完整处理的章节；批量处理默认跳过这些章节，也可开启强制重做。回导锁定的标注仍会保留。初读模式中被隐藏、未处理或未知的对白不会写入标注恢复清单。
- 当前以本地单用户使用为目标，没有账号系统或云端同步。
