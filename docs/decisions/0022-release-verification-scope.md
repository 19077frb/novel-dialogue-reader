# 0022 发布前验证口径：功能/稳定性/live/质量分开报告

日期：2026-09-28 · 状态：已采纳（T18）

## 问题

T18 要求「完整联调、体验与发布检查」，并明确报告**功能、稳定性、live 与质量四类结果**。
本机环境有三处硬约束：没有真实提供方凭据与预算、网络受限（无法下载 EPUBCheck 或安装阅读器）、
没有人工确认的真实作品样本。如果把这些混成一句「已验证」，就等于用假提供方或浏览器样张冒充真实能力。

## 选择

1. **四类结果分开写**（`docs/verification-report.md`）：功能与稳定性给命令与结果；live 与质量在缺证据时
   明确写 BLOCKED 并附上**具体检查证据**（环境变量无密钥、数据目录不存在、网络超时、无阅读器），
   不用「应该可以」代替结论。
2. **真实链路与真实模型分开**：E2E 用真实后端 + 真实 Chromium + 真实 TXT/EPUB，模型侧只用**显式启用**的
   FakeProvider（不访问网络）。因此「链路连通」可结论，「识别质量」不可结论。
3. **可访问性按可验证的不变量检查**：语言、标题层级、可访问名称、图片 alt、跳转链接、导航当前页、
   对话框语义（`role`/`aria-modal`/标题关联）、Escape 关闭与焦点归还、异步状态的 live 区域；
   不引入需要联网安装的检查器（axe 等），也不声称通过了完整 WCAG 审计。
4. **窄/宽屏按可用性检查**：360×740 与 1280×900 下五个页面不得出现横向溢出，关键控件必须可见可点，
   导出对话框不得超出视口；发现真实问题就修（本次修的是对话框/抽屉语义与键盘行为）。
5. **接口一致性用可执行的证据**：`npm --prefix frontend run check:api` 用 `docs/openapi.json` 重新生成
   `src/api/schema.d.ts` 并逐字节比对（已验证篡改时会失败），与 pytest 的 OpenAPI 一致性检查互补。
6. **边界按「拒绝 + 不泄漏」检查**：资源 id 越界、被篡改的源文件/产物路径必须走契约错误（404/409），
   不返回 500、不回显磁盘路径；密钥边界沿用 T06 的既有断言，不重复造轮子。
7. **不扩大功能范围**：T18 不新增产品功能，只修可访问性/边界/一致性这些真实缺陷。

## 被放弃的方案

- **用 FakeProvider 的 E2E 结果宣称「已完成真实联调」**：会掩盖「真实提供方未验证」这一事实。
- **用浏览器打开导出件代替独立 EPUB 阅读器试读**：浏览器样本无法证明阅读器兼容性。
- **悄悄跳过 EPUBCheck**：导出报告必须如实显示 `NOT_RUN`，不能用内部检查冒充标准检查。
- **为了让检查通过而放宽断言**（例如删掉密钥/路径断言）：这些断言就是任务的门槛。
- **引入联网的可访问性/标准检查工具**：环境不允许，且会把「装不上」变成假失败。

## 验证

- `scripts/verify.ps1` 退出码 0：`ruff` 全绿、`pytest` → **373 passed**、
  OpenAPI 与 `docs/openapi.json` 一致、前端 typecheck、**前端 API 类型与 OpenAPI 一致**、
  前端单测 → **72 passed**、前端 build。
- 全量 E2E：`npx playwright test` → **33 passed**（新增 `full-flow.spec.ts` 2 项、
  `a11y-layout.spec.ts` 3 项）。
- 边界：`test_boundaries.py` 3 项（越界资源 id 404 + 不回显数据目录；篡改 `source_path` → 409；
  篡改产物 `relative_path` → 404）。
- 接口一致性：`check:api` 在篡改 `schema.d.ts` 时返回 1（真失败），恢复后返回 0。
- **BLOCKED（有证据）**：环境变量无任何提供方密钥、仓库无数据目录（无保存凭据）、
  `https://github.com` HEAD 请求 6 秒超时、本机无 Calibre/Thorium/Adobe 阅读器、`tools/epubcheck` 无 jar。

## 后果

- 发布前的结论可以逐条复核：功能/稳定性有命令与输出，live/质量写清 BLOCKED 与原因。
- 拿到凭据/网络/阅读器后的动作：跑 B1–B4 得到质量结论；下载 EPUBCheck 跑标准检查；
  安装 ≥2 款阅读器做试读；把结果补进本报告并相应更新实现账本的 Live/Quality 列。
