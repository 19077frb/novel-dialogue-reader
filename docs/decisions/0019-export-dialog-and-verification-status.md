# 0019 导出界面与「验证状态说实话」

日期：2026-09-28 · 状态：已采纳（T15B）

## 问题

T15A 已经有导出后端，但用户还得用命令行。T15B 要把「选择 → 预览 → 生成 → 下载」做成界面，
同时守住两个容易走偏的点：**样张不能冒充成品**、**没跑的工具/阅读器不能写成 PASS**。

## 选择

1. **一个对话框，两个入口**：阅读页和预览页都打开同一个 `ExportDialog`，范围（整本/指定章节）、
   样式（颜色+编号/仅颜色/仅编号）、初读策略（初读安全/重读）、格式（EPUB/HTML）都在一个面板里完成。
2. **样张放在沙箱 iframe 里**：样张是后端导出渲染器的真实输出（`sample_html`），
   用 `sandbox=""` 渲染、不执行脚本；**不用阅读页截图冒充**。
3. **每次打开重新冻结快照**：对话框组件不会随关闭卸载，所以显式调用一次预览；
   比较**内容哈希**（`snapshot_hash`）而不是快照行 ID，只有标注真的变了才提示「旧快照」。
4. **生成幂等、下载受控**：同快照 + 格式 + 样式复用后端产物；下载走 `/api/exports/{id}/download`，
   文件名与 MIME 由服务端给出（中文文件名可用），重复下载不重新打包。
5. **失败如实展示**：内部检查逐项显示 ✓/✗，缺失片段与资源会列出来；`state != COMPLETED` 时不提供下载。
6. **验证状态分层写清楚**：内部检查 PASS、HTML 离线可读 PASS；
   **EPUBCheck = NOT_RUN**（本机没有 jar，也没联网安装）；
   **独立 EPUB 阅读器试读 = NOT_RUN**（本机没有安装任何阅读器）。这两项保留为未完成，
   不用浏览器或自研校验冒充。

## 被放弃的方案

- **把阅读页 HTML 截图当样张**：不能证明导出渲染器可用（违反“样张来自后端导出渲染器”）。
- **用行 ID 判断快照是否过期**：每次冻结都会产生新行，会误报；改用内容哈希。
- **下载时重新生成**：会绕过「快照冻结」与「幂等复用」；下载只读已有文件。
- **没有 EPUBCheck 就显示“校验通过”**：明确禁止；显示 `NOT_RUN` + 原因。
- **用浏览器打开 EPUB 冒充“独立阅读器试读”**：T15B 门槛明确禁止这种替代。

## 验证

- 组件测试：`ExportDialog` 5 项（冻结+覆盖/警告/沙箱样张、样式切换只改显示、指定章节传参、
  快照过期提示、失败不给下载）；前端 `vitest` 总计 **70 passed**。
- E2E（`frontend/e2e/export.spec.ts`）5 项：
  1. TXT → HTML：样张可见、校验报告（`text_consistency` ✓ / 标准检查 `NOT_APPLICABLE`）、
     下载文件名含「标注版」、成品**无 `http(s)` 引用、无 `<script>`、含 `〔S1〕`**（断网可读）；
  2. EPUB → EPUB：`mimetype_first`/`mimetype_stored`/`resource_closure` ✓、标准检查显示 `NOT_RUN`、
     重复下载文件名与字节数一致；
  3. 指定章节 → 文件名含「节选」，成品不含未选章节的正文；
  4. 未处理章节 → 覆盖统计显示「未处理 1」、警告列出「还没有标注」，下载成品里该对白保持原样（无 `speaker-`）；
  5. 并发纠正 → 重新打开对话框显示「旧快照」提示（生成时的文件不受影响）。
- 全量 E2E：**28 passed**（T15A 时 23）。
- 本轮修复的问题：①对话框只靠 `refetchOnMount` 不会在重新打开时刷新（组件未卸载）→ 显式重新冻结；
  ②`import-reader.spec` 的候选文本断言假设“这本书从未被处理过”，而新用例会先处理同一本书 → 改为包含匹配；
  ③导出测试原本复用 `sample-review.txt` 的内容，被 sha256 去重成同一本书导致卡片找不到 → 改用独立夹具。
- **未验证（保留）**：EPUBCheck 标准检查、独立 EPUB 阅读器试读（本机既没有 jar 也没有阅读器，
  且不能联网安装）。这两项不会被其它证据替代。

## 迁移与回滚

无迁移。回滚 = 删除导出组件与 `api/exports.ts`，并移除阅读页/预览页的「导出」入口；
后端导出能力（T15A）可独立保留。
