# 核心接口契约

机器可读的完整 API 定义见 [openapi.json](openapi.json)。本文件只保留跨模块必须遵守的语义约束。

## 响应与错误

本地窗口估算的 `windows` 含 `processing_status`（`completed` / `failed` / `unprocessed`）、`processed_target_count` 和 `last_error`。完成状态由当前已保存标注的覆盖率决定，不依赖浏览器任务列表；未完成窗口的失败状态来自该书籍版本中对应窗口的最近一次任务。查询不调用模型、不写数据库。补做窗口后，整章覆盖完整才写入 `dialogue_processed`；该状态优先于已结束批量任务的旧失败状态，正在重做时仍显示实时进度。

成功响应使用统一数据包：

```json
{
  "data": {},
  "meta": {}
}
```

错误响应至少包含稳定错误码、可读消息和请求 ID。校验失败应指出具体字段或模型输出问题；任何响应都不能包含 API Key、授权头或未脱敏的提供方内容。

## 文本坐标

- 所有正文范围使用规范化全文的 Unicode 码点区间 `[start_cp, end_cp)`。
- 后端负责码点与源文件位置的映射。
- 前端处理 JavaScript UTF-16 索引时必须通过统一转换函数。
- 模型通过稳定的 quote/gap ID 引用内容，不能自行计算字符偏移。

## 分页与只读性能边界

- `cursor` 是后端生成的不透明字符串，客户端只应原样传回，不解析或拼接。
- 书架与待确认列表按 `(created_at, id)` 排序，并使用同样的联合键继续分页，不能用随机 UUID 大小代替创建时间。旧 ID-only 游标在对应记录存在时仍接受；记录已删除时返回校验错误，提示重新读取。新游标不依赖上一条记录仍存在。
- 正文按 `(start_cp, chapter.ordinal, node.ordinal, id)` 排序并继续分页，保证同码点的图片/分隔符不会重复。兼容旧码点游标，但新的响应使用完整键。指定章节时必须限定 `chapter_id`，不能只靠码点范围，尤其是零长度插图章节。
- 批量装配不得改变人物名单顺序、相交标注的优先顺序或全书颜色身份。投影只能读取当前数据，不能缓存可变标注而漏掉人工更正或初读身份还原。
- 待确认统计分别保留原因记录数量和不同 quote/gap 目标数量；不得为统计读取完整候选 JSON。任务进度与用量汇总只读取统计必需字段，不改变未知用量和重试归属。

## 原文和导入

- 原始文件和规范化正文不可变。
- TXT 必须严格解码；失败时可以返回候选编码预览，但不能把替换字符写入正文。
- EPUB 按 spine 顺序读取，只允许访问包内登记资源。
- spine 文档不等于章节。有效 nav/NCX 目录的 `href#fragment` 优先决定章节边界，按 spine 中的真实位置排序；不列入目录的文档延续当前章节，首个边界之前的文字保留为卷首，纯图片前缀并入首章。同位置的卷级及叶子链接优先使用叶子并保留卷名前缀；缺失正文/锚点记录警告，无有效边界时回退文件划章。内联锚点拆分不得插入额外换行或丢弃文字，source_map 保留原文档路径及局部位置。
- 纯图片章节并入相邻正文，图片顺序不变，纯图片书保留一章。带 `OEBPS/annotations.json` 的回导文件保留原章节边界；不自动迁移已持久化书籍的章节和标注。普通 EPUB 的正式章名不能仅因标点、长度或编号而自动合并；导入后的章节检查只可保守合并标题-only 的重复序章。原文件重新导入的新 parser 版本不覆盖旧版本正文，也不自动迁移旧版标注及处理状态。
- EPUB 正文首先严格按 XML 解析；仅在失败时，将带分号的标准 HTML 字符实体（如 `&nbsp;`）转为数字引用后再严格解析，不加载外部 DTD、不执行脚本、不修复错配标签。未知实体、缺失分号及其它 XML 错误仍拒绝，并返回文件路径与解析原因；成功兼容的正文文件记入导入警告。原始文件不改写，CDATA/注释中的字面文本不替换，含自定义实体声明的文档不做此兼容。
- EPUB 的装饰性分段通过 `tinycss2` 和 `cssselect2` 读取静态 CSS 提示，不把原始 HTML/CSS 注入阅读页。仅候选容器的 3～160 个非空短段（每段最多 12 字、合计最多 160 字）可在竖排/浮动证据充分时去除人工段界；不跨图片、正文长段、脚本或不同文档，不改动文字、注音或原文件。CSS 的层叠、内联优先级与 `!important` 用于 float/writing-mode 提示；不执行生成内容、字体、URL、`@import` 或媒体规则。单样式上限 128 KiB、单文档 CSS 总量上限 512 KiB、最多 2048 个相关选择器，超过限制或不支持的样式不参与整理。回导带标注的文件跳过此整理；新导入使用新的 parser/normalization 版本，已有持久化正文不迁移。
- 重新导入或更换编码应创建新版本，不能修改旧版本。
- `PUT /books/{book_id}/chapters/{chapter_id}/processing-status` 接收本书版本及 `dialogue_processed`：布尔值写入持久完成标记和 `processing_status_override`；显式 `null` 仅解除保护，不改现有完成标记。目录返回保护值，手动状态优先于旧批次及正在运行的状态；该操作不修改 Job 状态、标注、用量或正文。人物任务、整章任务收尾及窗口覆盖确认不得覆盖保护值。章节/版本归属必须校验；只有新的单章正式处理或批量（含自动/重试）流程开始时解除保护，试运行/局部复核不解除。
- 无正文文字的章节，在导入或人物任务执行时持久化 `dialogue_processed=true` 及已确认的空人物名单，无 POV。判定为 canonical 切片折叠空白后为空，或唯一文字与章节名一致且具有标题节点（标题不计作叙述正文）。人物任务以 `COMPLETED` 结束，进度 `skipped_reason=no_text`、`calls=0`，不构建模型适配器、不创建 InferenceRun。启动时检查未完成且字符长度不超过章节名长度加 64 的候选章节，复用 canonical 缓存补齐旧状态；缺失或不可读文件跳过检查、不改为完成。章节名含插图、没有对白、模型返回空名单均不单独构成完成依据。

- 原文中的跨段未闭合 `“` 可在导入时生成段内虚拟 `”` 修复建议；扫描时应用，canonical 正文不可改写。
- 修复建议必须可查看、可编辑和可停用；重新检测或调整后只重建候选边界，不得清除或覆盖已有标注、对白归属和人工锁定结果。

## 人物和场景

- 章节人物记录跨场景身份，场景说话人记录当前对话参与者。
- `EXISTING` 只能引用当前场景已经声明的人物。
- 场景切换后，人物需要通过 `NEW` 和 `new_speakers` 在新场景重新声明。
- 已经由用户确认的人物姓名、身份和对白不能被模型输出覆盖。
- 人工更正对白时优先使用该对白标注已保存的场景归属。只有没有有效归属时才按位置寻找/创建场景；独立处理范围可能留下重叠开放场景，不能依赖数据库返回顺序覆盖已有归属。
- 新的模型调用要求 `new_speakers[].name` 和人物分析的 `characters[].name` 填写非空、最长 32 字的简短姓名或称呼；人物身份、动作和关系放 `description`，不能用说明句或 S1/S2 替代名称。对白调用缺少合法名称会走现有有限校验重试；人物分析缺少合法名称则显示任务失败。历史缓存的解析仍兼容旧字段，提示词版本升级后新调用不会复用旧提示词结果。
- 姓名与别名唯一匹配时优先关联已确认身份；括号说明及明确“职务+姓名”可用于匹配，不使用任意子串或关系描述猜测身份。共享别名存在歧义时不自动合并；通用匿名称呼如“男生”“轻浮男客”不单凭同名自动复用身份。人物候选若匹配同一稳定 ID，只保留一项并合并证据和视角候选状态。
- 全书人物管理使用 `GET /books/{book_id}/character-directory`，包括全书身份和未关联身份的场景说话人（`kind=speaker`、ID 为 `speaker:<group_id>`），不按同名自动归并。`PUT /books/{book_id}/character-directory/{entry_id}` 编辑姓名、别名、说明；保存场景说话人会创建并关联人工确认的全书身份。`POST .../{entry_id}/merge` 将来源关联到另一个本版本全书身份，同步现有分组、章节候选/确认 ID/主人公以及非已完成任务的恢复快照，移除被合并的全书身份；不改变对白判定、原文或章节完成状态。合并保留原姓名和别名，优先保留目标说明，不能自动撤销。写请求校验来源及目标版本（过期返回 409），跨书/失效人物返回 404；本版本存在 QUEUED/RUNNING/PAUSING 任务时返回 409，操作不调用 LLM。目录为全书视角，不受初读 horizon 限制，必须提示剧透。
- `UNKNOWN` 表示证据不足，不等于新人物。
- 场景切换必须有正文证据；普通叙述、心理描写或固定长度不能单独触发切换。

## 任务、缓存和幂等

- 局部复核 `POST /quotes/{quote_id}/recheck` 同样支持可选 `inference_options`，使用与对白处理一致的校验、任务快照和参数摘要；不指定时继承模型配置。复核面板共享模型选择、思考模式和强度偏好，输入额度仍单独确认；运行中禁用本面板配置和重复启动。完成或停止后的显式再次复核使用新的幂等键；传输重试保留原键。

- 模型配置的 `params.thinking.type` 和 `params.reasoning_effort` 可在配置页作为默认值编辑。任务中 `default` 表示继承已保存值，没有已保存值时由提供方决定；实际思考模式（含继承默认）为 `disabled` 时，快照移除 `reasoning_effort`，不修改配置本身。

- 对白任务和章节人物识别请求支持可选 `inference_options`：`thinking_mode=default/disabled/enabled/adaptive`、`reasoning_effort=default/low/medium/high`。只覆盖任务配置快照中的 `thinking.type` / `reasoning_effort`，不修改模型配置；关闭思考时删除强度参数。覆盖项参与请求摘要和现有缓存的参数摘要，幂等键不能用于不同设置；后续编辑模型配置不改变已有任务快照。客户端共用一份记忆设置，运行中禁止修改。提供方必须支持相应参数；程序不自动提高输出上限或超时。

- 创建任务的幂等键只能复用完全相同的请求摘要。
- 同一幂等键对应不同请求时返回冲突。
- 缓存键由语义输入生成，不包含任务 ID 或预览/正式处理标签。
- 已完成窗口可以复用；结果未知的远程调用需要用户明确选择是否重试。
- `POST /api/jobs` 开启 `run_now` 后由后台执行，返回的 `QUEUED` 是创建时快照，不是任务失败。单章多窗口派发必须只读跟踪每个任务的实际终态，终态前不得释放并发槽位；提交后立即展示任务 ID 对应的执行面板及逐窗口状态。`NEEDS_RECONCILIATION` 停止自动等待，交由用户确认，不能自动重发调用。提交或有限进度读取重试失败时保留任务记录并停止后续窗口派发，不能伪装为完成。
- 暂停在窗口边界生效，恢复后不得重复提交已完成窗口。
- token 用量缺失时记录为未知，不能按零处理。
- 任务详情 `usage` 同时汇总 `input_tokens`、`output_tokens`、`total_tokens` 和 `unknown_runs`，覆盖本任务全部调用尝试（包含失败及校验重试）。总量优先使用每次提供方上报的 `total_tokens`，缺失时合计该次输入、输出；全书用量采用同一口径。批量额度刷新不清零结束报告的累计消耗，未知调用单独标识，不充当零用量。

## 处理范围、模式和批量顺序

- `DELETE /api/books/{book_id}` 删除指定书籍及关联数据库记录，成功返回 204，不存在返回 404。若该书有 QUEUED/RUNNING/PAUSING 任务则返回 409；前端还需阻止当前会话正在运行的批量调度删除。先完成数据库级联清理，再将独占书籍与导出目录移入数据目录 `trash/` 并提交事务，避免耗时清理期间正文文件提前消失；外键引用列须有前导索引以避免逐行全表扫描。文件移动或数据库事务失败需回滚；文件占用或权限问题返回 503 和明确提示。删除请求未结束时，目标卡片禁止进入阅读。不得按书名删除，也不得操作其他书籍或用户原始上传文件。应用内无法撤销，回收区仅保留文件，不保留数据库标注。

- 批量默认跳过 `dialogue_processed` 章节；显式开启强制重做时，预估与执行必须包含这些章节。`POST /api/jobs` 的 `force_reprocess=true` 跳过模型结果缓存（包括复核），但不解除人工标注锁定，也不改变请求幂等约束。

- 预览与处理入口必须先选择单章或批量模式，只展示当前模式的配置。两种模式必须共享同一份模型配置 ID、每窗口复核数、并发上限及额度数值，并在当前浏览器同源本地存储中记忆；跨书/切换页面/重新打开应恢复，不能保存密钥。单章输入上限与批量本次累计额度共用数值，单章额外的输出上限也记忆；不改变原有预算执行口径。范围、窗口勾选及强制重做不记忆。已删除的模型配置应回退到可用配置，无可用配置时阻止启动。存储损坏使用默认值，存储被禁止时仅保持内存配置。运行中的任务仍使用启动时配置；批量运行中的额度调整原地生效并保存到共享配置。
- 单章窗口预览是本地只读计算，不调用模型，也不写入标注结果。
- 单章对白任务可以提交一个或多个窗口；窗口选择只限制对白归属推理，人物表分析始终使用完整章节正文。多个窗口受用户配置的并发上限约束，整章 token 上限按窗口估算比例分配。
- 批量人物分析必须严格按章节顺序执行，前章人物确认请求成功返回后才可启动下一章人物分析；人物任务之间不得并发。若前章人物识别或确认失败，记录失败并跳过其对白，随后可继续下一章；空人物名单不视为失败，跳过本章对白，不写入章节完成状态。已确认章节对白可与下一章人物分析并发，所有模型任务共享同一个并发上限。
- 单个章节或窗口失败只影响自身，不得把后续任务统一标为失败；用户主动停止或批次 Token 上限耗尽才触发安全停止。
- 并发窗口独立使用已确认的整章人物表，不要求消费其它并发窗口执行期间产生的临时场景状态；需要最强跨窗口连续性时并发数应设为 1。
- 批量运行期间，处理入口必须显示持久的任务进度（任务类型、章节、窗口和状态），并禁止切换模式或创建另一个任务。进度状态在应用内切换页面后仍须可恢复显示。
- 批次结束、失败或停止后，任务列表和具体错误仍须显示，配置入口恢复可用；应用内切换页面和模式不清除结果。当前会话保留最近一次批次，下一批启动替换列表，浏览器刷新或关闭后不保证恢复。
- 停止批量处理采用安全停止：排队任务不再派发，已经提交给提供方的请求允许收尾，且停止入口在批次终止前始终可见。
- 阅读目录的实时状态必须区分排队、人物识别、对白窗口进度、完成和失败/停止。任务行更新不得使阅读页重新请求目录或标注；窗口完成只刷新当前章标注，整章完成才刷新目录，短时间内的同类刷新必须合并。
- 目录的完成状态只读 `chapters.dialogue_processed`；旧任务状态由迁移一次性回填，读请求不得重复扫描任务历史。
- 书籍、目录和正文等只读查询只可对网络错误、限流和服务端临时错误做有限重试；最终失败必须展示具体原因和显式重试入口。
- 已确认的书籍人物可以作为后续章节的人物上下文，但不能替代对当前章节人物的重新分析。
- 批量 token 预估必须在正式启动前完成。设置上限时，用量未知不能视为零继续执行。
- 并发拆分任务不能直接宣称整章完成；只有本章全部外层候选对白都有当前标注后，覆盖校验接口才能写入已处理状态。
- 调大 token 上限只更新当前批次的限制并保留已消耗量，不得重建或重跑任务；额度刷新操作可以重置当前批次的额度计数，但不能删除已有处理结果。

## 模型输出

- 模型必须返回符合 schema 的 JSON。
- JSON 解析、字段约束、目标覆盖、引用完整性和场景状态全部由后端校验。
- 只允许修复不会改变语义的确定性错误。
- 每个 Gap 的输入明确给出后续首个目标对白引用（无则为 null）。场景起点只能使用目标对白，尾部无目标的场景变化延后处理。只读重叠引用误用为尾部起点且新场景未被任何目标或人物使用时，可撤回该无效声明并记录修复；目标场景/人物冲突或编造引用不得据此放宽校验。
- `max_rechecks` 限制首次有效结果中待定对白的复核数量，显式值（含 0）覆盖上下文策略默认值。`budget.max_format_retries` 独立限制对白输出校验错误的纠错重发次数（不含首次，默认 1、范围 0～5；旧任务缺少字段时按 1 执行），适用于首次标注、局部复核及自动待定对白复核。每次重试重新检查停止状态与剩余额度，所有尝试分别留痕并计入用量；有限额度下已用量未知的调用按估算预留。普通复核最终失败保留首次标注及窗口完成状态，额度不足时跳过额外复核；结果未知的超时转人工核对，不自动重发。人物识别和提供方限流退避不受此字段控制。
- 格式重试和语义复核均受次数与预算限制。
- 证据不足的结果进入待确认队列。

## 人工更正

- 人工操作不调用模型。
- 更正以追加历史记录的方式保存，并支持有版本约束的撤销。
- 旧版本提交返回冲突，不能静默覆盖较新的修改。
- 更正可能使同一窗口或场景的其它自动结果失效。
- 被用户锁定的结果是后续处理的权威输入。

## 导出

- 导出基于不可变原文和冻结标注快照。
- 新快照同时冻结章节完成状态和手动保护值，加入快照哈希；改变完成标记后重新预览不会复用旧状态的 EPUB，旧预览仍保留其冻结状态。历史快照不含状态字段时保留读取实时章节状态的兼容路径。
- 导出过程不调用模型，也不覆盖源文件。
- 未处理、未知或失效对白保留原文，不添加错误标签。
- EPUB 导出可以携带版本化的本地标注清单；重新导入时只恢复清单中与章节及对白原文匹配的可见标注，匹配失败不得阻断正文导入。
- 标注清单必须记录已完整处理的章节；回导后目录和批量任务都以该状态为准，默认不得再次调用模型处理这些章节；仅用户显式开启强制重做时可重新处理，仍保留回导锁定标注。
- 清单的可选 `manual_processing_status` 以导出章节下标字符串映射布尔值，保留用户手动完成/未处理标记。回导以章节绑定恢复且优先于默认无正文完成规则；无效下标或非布尔值忽略，不改变正文匹配。旧清单无此字段时保持原行为。
- 回导恢复的不同人物身份不能仅因显示名称相同而合并，恢复结果必须锁定，后续自动处理不得覆盖。
- EPUB 不包含脚本或远程资源；HTML 应可离线打开。
- 相同快照、格式和样式的请求可以复用已有产物。

## 安全

- 服务默认只监听本机回环地址。
- 模型密钥只进入系统凭据库或会话内存。
- 原文、数据库、导出文件和日志保存在 `NDR_DATA_DIR`，不得提交到 Git。
- 日志、任务错误和调试片段必须脱敏。
