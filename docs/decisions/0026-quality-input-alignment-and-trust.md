# 0026 对白质量修复：输入对齐、人物作用域与可信状态

日期：2026-09-28 · 状态：已采纳（Q01–Q04 已实现；Q05 真实模型对照待用户触发）

## 问题

《义妹生活 第一卷》序幕的实际结果暴露出四类系统性问题：模型收到正文和 ID 的两份独立列表，无法可靠对应；人物语义描述和合法引用脱节，`new1` 等临时引用还会跨窗口残留；模型自报 `DIRECT` 并只引用候选自身时也会被标成已接受；缓存、预算和失败用量没有完整覆盖实际请求。

这些问题会同时造成非对白被着色、同一人物多色、不同人物同色，以及界面显示的“已接受”数量虚高。此时直接换模型或扩大上下文不能解决根因。

## 选择

1. 每个窗口给片段分配 `Q1/G1/E1` 短引用，并把 `ref/kind/start_cp/end_cp/text` 放在同一条 JSONL 记录中。模型返回后，后端在校验和落库前恢复为稳定 ID。
2. 只把当前场景的 `S1/S2/...` 展示标签暴露为 EXISTING 合法引用，并发送“标签—描述—本窗证据”的人物表。`newN` 仅在一次响应内有效，成功应用后清除。
3. `kind=unknown` 进入 UNKNOWN；`basis=DIRECT` 只有在引用候选自身之外的证据时才自动 ACCEPTED，否则进入 PROVISIONAL 与确认队列。接受策略版本升级为 `acceptance-2`。
4. 缓存对最终消息、动态人物状态、提供方端点、提示词版本、上下文策略和接受策略取指纹；缓存格式升级为 `cache-2`，隔离旧结果。
5. 适配器在解析响应前保存 usage；无效 JSON 等失败仍记录已知用量，缺失用量的远端无效输出按未知费用计。预算预留按最终实际消息重新估算。
6. 结构化记录存在时，不再在任务参数中重复目标、Gap、证据 ID 列表；schema 和任务 JSON 使用紧凑序列化。序幕两个窗口离线估算为 5556/5534 输入 token，稳定 ID 泄露均为 0；与修复前约 5625/5506 基本持平，同时获得逐段精确对齐。

## 验证

- 回归覆盖短引用恢复、动态人物状态/端点/接受策略缓存失效、临时人物引用清理、UNKNOWN 状态、DIRECT 自引降级、无效响应 usage 保留。
- Ruff 全量静态检查通过。
- 后端完整测试通过（测试命令：`python -m pytest -p no:cacheprovider backend/tests -q`）。
- 使用现有《义妹生活》数据离线重建两个序幕窗口；没有调用 DeepSeek、读取密钥或改写现有标注。
