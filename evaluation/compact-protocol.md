# 隔离短归属协议评测

本入口面向评测维护者。正式任务API和页面已有显式短协议试验入口，见[任务契约](../docs/CONTRACTS.md#人物身份与颜色)；默认任务仍使用原协议，本页隔离实验不自动修改阅读、单章、批量或局部任务，也不会自动更改思考设置。不能将协议合法率提高当作人物归属质量提高。

显式1.1领域应用保留编译后的身份区分：已有身份以当前书籍的稳定ID关联，新身份不因同名或相同匿名称呼关联旧人；同一声明重复应用用确定性临时键复用，检查点恢复保留此模式。旧1.0任务与旧检查点保留兼容逻辑。正式Jobs的`expression-production-1`任务冻结有效人物视图、真实窗口与稳定ID映射，并使用同一短协议编译；已知ID的空名豁免只用于程序声明，不适用于新N人物。独立实验CompactTask仍要求初读字段符合其提供的逐事实依据，不能拿生产有效资料修订伪造原文事实。正式Jobs采用[人物输入可见范围契约](../docs/CONTRACTS.md#模型配置任务和恢复)，该安全边界不是本页隔离实验的新质量成绩。

正式人物识别和对白提示的格式示例使用原创人物，不嵌入评测小说的人名；真实任务输入的人物资料不作替换。示例调整计入各自提示版本和评测版本记录，不能把旧缓存、旧模型输出或历史报告当作新提示的质量证据。独立验证作品也应避开示例人物，并做实体替换对照。

## 输入、编译与可见范围

`ndr.evaluation.cold_roster`提供独立空名单提案实验：`ColdRosterTask`只发送显式可见范围内的原文行和空目录，模型为每个身份分别列出姓名、别名、说明、关系及各自的原文L证据。姓名/别名必须在其引用中出现，每条事实的可见时点取自身证据的最晚结束位置；说明/关系可以概括，但引用存在不保证语义正确。程序不按同名合并不同身份，POV只能引用提案内身份或为null，空名单合法。`compile_roster`生成隔离身份和`EvidencePerson`供现有检索使用，不写书库，不等于全书身份链接已完成。

`run_cold_roster`仅调用显式提供的适配器，保持输出上限、有界格式重试、原始输出和全部已知失败消耗；用量未知即停止并不返回可接受的人物名单。持久化、模型参数指纹、授权和预算仍由调用者管理。冷名单提案到全章归属、人物召回/重复/误合并、匿名分组及初读未来泄漏必须另行真实评估，不能把离线夹具当模型质量。

空名单提示版本为`original-fact-roster-5`：没有实名时要求以`designation`记录原文可区分代称，而不是只给别名或因此返回空名单；同一身份的同种同值事实只列一次，合并其不重复的原文引用。后文实名仍作为有独立依据和可见时点的新姓名事实。程序仍拒绝无姓名/代称、重复事实、人称代词及无字面依据的姓名，不静默修补或合并身份。版本进入任务指纹，旧记录不得充当新版本结果；提示要求不保证模型一定遵守。

正式人物分析使用独立的`sourced-roster-2`内部1.1输出，按身份依赖隔离错误并保留独立有效的提案；旧版本任务保留其原校验语义。已写入书库的逐事实记录遵循[人物契约](../docs/CONTRACTS.md#人物身份与颜色)。它保留现有章节确认流程及明确的全书身份引用，显式短对白任务使用有效资料另行绑定；不能引用隔离实验成绩作为新版生产协议的质量成绩。

离线回归：

```powershell
uv run --project backend python -m pytest backend/tests/unit/test_cold_roster.py
```

`ndr.evaluation.compact.CompactTask` 接收有序目标Q引用、Q/G/E到原引用的一对一映射、原文片段、候选人物及Gap的下一条目标。`Candidate`使用本次C编号，稳定人物ID只供程序映射；目录不代表在场。未列入人物可通过带原文证据的N编号声明，不确定仍为UNKNOWN，不根据同名或相似描述合并。

模型只输出类型、人物、依据、证据引用和场景切换建议。非speech分支不含人物字段；程序按原文顺序构造场景内NEW/EXISTING，跨场景重新建立局部分组但保留稳定人物ID。语义切场景仍由模型建议，程序不猜测。`compile_output`复用现有严格输出校验，整个依赖块有效才返回，不逐条写库，也不放宽生产事务。

初读输入必须显式指定可见范围，拒绝超范围原文及候选身份；调用者仍须核查名字、别名和说明各自的揭示时间，单一可见字段不能证明资料没有未来信息。重读允许显式提供更宽资料。指纹包含协议/提示/编译器版本、原文、引用映射、人物稳定ID、场景和阅读范围；本入口不共用生产缓存。程序生成的场景和人物临时引用带任务命名空间，不与已有输入引用复用。

## 证据检索与关联复核

`ndr.evaluation.evidence.EvidenceIndex` 接收固定正文快照和稳定人物列表。`IdentityFact` 将姓名、别名、说明、关系分别记录可见位置、来源和可选原文范围；关系不作为别名，同名人物不合并。证据不能晚于资料的可见时点或越出正文。初读逐条过滤资料与原文；没有可靠资料历史时不能把整章名单伪装成初读安全名单。

按目标附近姓名命中选择候选，保留指定参与者和POV，按每个人的数量上限返回外部原文锚点；8/16/32条窗口仅是实验档位，并非已证明的最佳值。姓名命中、发言动词、称呼和进出场提示都是检索线索，不是身份结论。目标、间隔、证据保留原字符坐标。

`ndr.evaluation.risk.detect_risks` 覆盖已接受项的分层抽检、窗口边缘、未知与非对白类型、缺少外部证据、DIRECT关系未核实、新身份、共用证据冲突、未知或弱依据依赖、称呼冲突，以及模型对当前目标的补充上下文申请。申请只能使用本次目标Q引用，不会自动扩大初读范围或发起额外调用。`review_blocks` 将附近目标合为关联片段；`risk_scores` 依据标准答案分别计算错误召回率和正确项复核比例，不把UNKNOWN当作正确项。这些规则尚不是校准过的正确性概率，不能凭触发或未触发宣称归属正确。

`ndr.evaluation.review.run_linked_review` 显式选择独立判断或展示旧候选；独立输入不追加旧回答，候选输入标明旧答案不是事实。`reconcile` 保留人工锁定及未收到有效复核的原结果；同一人物/类型的复核若依据更弱，也不覆盖原有有效外部证据，不把同名重复判断当作新证明。真正分歧不会默认采用第二次答案。可提供有外部证据的第三次判断进行佐证，仍有冲突则保留UNKNOWN。证据存在也不代表语义充分，须测纠正数、误改数与增量消耗。匿名身份按调用隔离，不因相同称呼跨调用合并。

`compile_decisions` 将完整结果重新编译，程序重建首次出现及场景内编号，不逐句修补生产状态。调用者必须显式提供批准的场景边界、匿名声明及复核引用的完整原文；身份或证据不在快照时拒绝编译。以上入口只返回提案，不写实际书库，也没有自动接入现有整窗复核或后台任务。

## 跨窗口接力与场景依赖

`ndr.evaluation.relay.attach_relay` 仅将完整前窗结果作为未确认候选，携带最多8条原文轮次、每条最多3处原文证据及有界追加字符。人物按稳定ID重新映射；本窗名单缺少该身份或前窗为匿名身份时保留未映射，不依据同名强行关联。依据强弱只是结构提示，不是正确性概率。传递文本须位于本窗之前，重叠快照须完全一致；初读可见范围不扩大。超限可省略整条轮次或证据，不截断对白来伪装完整原文。

`attach_dependency_relay`将显式依赖的多个前窗合并到同一预算：总计最多8轮、每轮3处证据、额外原文默认4000字符，而不是每个父窗各有一份预算。优先最近父窗，再按原文顺序展示候选，全部父窗仍须通过严格原文/完整输出校验。执行器不仅等待跨场景依赖，也传递其未确认原文候选；跨场景不继承人物槽位，不传递未声明依赖的其他并行窗口。

`ndr.evaluation.scene_plan.validate_scene_plan` 验证调用者显式提供的 `scenes`（每组含 `scene`、`windows`、`depends_on`），按原文有序覆盖每个窗口一次。场景内窗口顺序依赖前窗，跨场景依赖只能引用先前场景；结构有效不证明语义独立。`comparison_plan` 单独生成独立窗与全连续窗对照，不自动推测场景。这些纯函数本身不启动后台任务，也不保证实测吞吐。

`ndr.evaluation.scene_planner.run_scene_planner`通过调用者提供的授权适配器显式生成计划，只输入固定原文及有序窗口字符范围，不包含人物归属答案。默认规划输出上限4096、最多一次格式重试，仍由上述验证器检查完整覆盖与依赖；无效计划不会自动替换成串行或独立计划。模型若只提出一条连续链也保留该结果，不为提高并发反复规划。提供方失败或未知用量停止，已知格式失败费用保留；使用`planner_fingerprint`（模型/思考签名、原文、窗口、策略与版本）配合独立`JournaledAdapter`可恢复已付费响应。规划成本与墙钟必须单列并计入计划并行方案的完整成本，结构通过不能证明场景语义正确或实际加速。初读调用者须显式只提供允许范围，入口不自行读取其他章节或资料。

`ndr.evaluation.pipeline.execute_pipeline` 显式接收授权适配器、独立调用账本、完整原文、窗口与依赖计划。`PipelinePolicy`固定模型/思考设置签名、策略版本、输出上限、格式重试及1～2并发；原文、人物、计划及版本共同进入`pipeline_fingerprint`，不共用生产缓存。运行前核对全部片段与原文一致、目标不重叠、同链顺序；独立链可并行，失败父窗只阻塞其依赖链。

`ndr.evaluation.scene_state`为独立计划场景分配确定性命名空间，同链后窗承接前窗最后目标所在场景的已知人物槽位。稳定身份相同才复用；本窗人物姓名、别名、说明与可见时点不从前窗覆盖。前窗发生切场景时只承接末场景，匿名或未映射人物不根据相同名字自动关联。输入显式槽位与前窗状态矛盾时拒绝运行。此状态衔接与是否展示原文接力候选分别控制：关闭`relay`不会将同链已有稳定人物重新声明为NEW，也不代表程序自动确认前窗身份判断正确。版本变化须使用新账本，不能将旧实验的恢复记录作为新策略效果。

恢复已完成窗口时再次核对输入和证据指纹，不调用模型；未完成但已记录响应由账本复用。未知用量停止新请求。取消或配置版本变化不强制中断付费网络请求：在途响应继续记账，旧版本结果不得提交检查点；恢复须显式解除停止。返回本次真实新增调用/Tokens、累计账本和本次墙钟，不将缓存恢复当作新的模型速度测量。

可通过显式窗口处理器组合`ndr.evaluation.window_review.refine_window`。它先完整初判，再按风险合并关联片段、扩展原文并选择独立或候选复核，保持原人物快照与初读范围。已知用量的复核失败保留合法初判并单列失败；语义分歧不默认采用第二次回答。人工锁定保持，匿名声明按源隔离，结果带完整原文引用后再严格编译。调用者必须给自定义处理器独立策略版本；执行器拒绝暗改输出上限。这仍是隔离提案执行，不代表阅读、单章或批量产品任务已接入。

离线接力及计划回归：

```powershell

uv run --project backend python -m pytest backend/tests/unit/test_compact_scene_state.py backend/tests/unit/test_dependency_pipeline.py backend/tests/unit/test_window_review_pipeline.py
```

模型对照由维护者显式提供适配器，调用`ndr.evaluation.compact_trial.run_trial`。短协议默认使用task.messages()；旧协议需同时提供legacy_messages和legacy_targets。返回原输出、完整编译结果、每次尝试的用量/失败原因/时间、首次合法率和未知用量次数。每窗最多额外0～5次格式重试，默认1；超时、限流、鉴权或网络错误不自动重发。每次输出上限显式固定，重试不暗换模型、思考设置、文本或上限。没有任何隐式强模型兜底。

短协议默认启用`targeted_retries`：可定位的结构错误只重试受影响目标及其依赖闭包。引用该目标的证据链、共用的新人物声明及声明自身引用的目标证据一起隔离；已独立通过结构校验的标签暂存，不视为已确认正确。所有原文、候选资料与可见范围保留，不新增上下文或逐句调用。重复/缺失/未知目标、无法定位声明、无效场景等整体错误仍整窗重试。局部回复不能更改原场景建议或复用保留的新人物引用，不根据相同姓名合并匿名人物。

后续回复与保留提案合成后仍须通过完整窗口的严格编译，才返回成功；耗尽重试或用量未知不返回部分输出。`requested_targets`、`retained_targets`记录每次实际请求范围，`final_payload`保留最终合成提案，原始失败回复仍在`attempts.raw`。首次合法率与失败消耗不因修复成功而重写。显式设`targeted_retries=False`可做整窗对照，旧协议始终保持整窗重试；调用策略及版本需进入调用者恢复指纹，不能用旧账本冒充新策略。

未知用量即使发生在格式错误时也会停止后续重试，并返回`reconciliation_required`；调用者须停止新增窗口并对账，不能把未知消耗记成零后继续。此标记不是自动恢复或持久化机制。

此函数不保存数据库或运行记录；调用者须在每窗之后持久化内部结果、禁止静默覆盖旧实验/重复发费，核对提供方实际模型及thinking参数。请求会发送提供的原文，真实运行需明确授权数据和端点，并另外约束总调用数及费用；该离线命令不代表已授权付费。

## 持久化、预算与恢复

`ndr.evaluation.adjudication.adjudicate_window`提供显式第三判断实验入口，不接入生产任务。调用者传入完整原文任务、原始与复核判断、人工锁定以及不含凭据的实际模型/思考参数签名。只对未解决分歧、请求上下文或弱证据目标触发，关联邻句合并为最多16条的片段，每片段一次判断及显式格式重试。第三判断独立看原文，不提示旧答案；邻句不改写。默认分歧仍要求第三判断与已有候选之一一致。显式`allow_new_identity=True`时，实际分歧目标也允许第三种已提供稳定身份，但必须有direct/coreference/response_link及目标之外的合法原文依据，并通过整块编译；新匿名人物、弱依据或仅自引不能套用此规则。非冲突仍只能同身份加强依据，人工锁定优先；匿名跨调用不按姓名匹配。入口在调用前冻结输入，结果记录模式、版本与含任务/原文/判断/锁/预算及模型范围的裁决指纹；旧原始响应的重新解释是新策略结果，不算新远程请求。证据条件不是语义正确保证，仍需金标准评测。这一入口仍是1.0提案，不代表三种表达的正式1.1裁决已接通。

调用者显式选择全禁思考或低思考适配器，固定相同上下文、触发集和输出上限，记录提供方实际参数、模型、思考可得性和全部消耗。函数不会暗换模型、开启思考或增加预算。已知失败保留合法现状；未知用量返回未完成和保留结果，不能推进任务。持久化与参数/来源指纹由下面的账本负责，函数本身不写书库或保存状态。恢复回放费用不重复相加；第三判断费用须与首次、复核及规划成本合并报告，而不是只展示升级调用。离线回归可执行：

```powershell
uv run --project backend python -m pytest backend/tests/unit/test_risk_adjudication.py
```

可显式以`ndr.evaluation.journal.JournaledAdapter`包装已授权适配器，使用`CallJournal`的独立`*.trial.sqlite3`文件。该文件包含正文响应和评测检查点，必须放在本地被忽略目录，不上传。账本不读取应用配置或生产数据库；会拒绝非专用文件及其他模块的数据库。

调用者提供包含协议/提示、模型/思考、资料快照和策略版本的依赖指纹；指纹变化须使用新账本。每次消息与输出上限也进入请求指纹。已完成响应及已知用量失败可复用，不重复请求；回放用量标记`journal_replay`。账本按唯一实际请求累计消耗，不能把多次回放的试验结果用量重复相加。只有未知消耗或旧进程在途记录时，禁止新增请求，不能仅因进程退出就认定请求未计费。`reconcile`要求已核实用量及审计说明；只有账单而无响应时，同一请求仍不会自动重发。

并发调用先在短事务中预约次数和估算Tokens，网络等待不持锁。估算使用请求UTF-8字节、输出上限和额外余量，**不是精确tokenizer或提供方费用硬限制**；若提供方实际用量超过预约，照实记录并阻止后续超额调用。失败用量计入，未知不记零。取消或预算调整须通过带版本的`configure`；停止阻止新请求，在途响应仍入账，但旧版本结果不得推进检查点。恢复保留已付费响应和检查点，不表示生产任务已接入此实验恢复机制。

覆盖已有检查点还须比较调用者读取的原值；仅比较全局版本不足以避免同版本并发覆盖。原值已变时拒绝提交，相同结果重复保存保持幂等。

离线账本回归：

```powershell
uv run --project backend python -m pytest backend/tests/unit/test_trial_journal.py
```

对照保持模型、思考、候选名单、文本、窗口、并发和重试额度相同；先比较协议，后加检索、风险复核及接力，不能一次改变所有变量。固定名单实验只隔离对白模块，不代表空名单完整人物流程。旧失败输出重放只测解析，不能冒充新调用效果。

`identity_scores`按目标引用与稳定人物身份逐项对照，计入错误、UNKNOWN和缺失；人物A/B全交换也算错。与[匿名分组指标](ablations.md)并列报告，不能相互替代。实际总Tokens、失败消耗、未知用量、调用秒、墙钟、窗口完成率、正确覆盖与错误率都应报告；来源核查、开发集与独立人工金标准要分开标明，单章单次不作总体能力或非劣承诺。

## 表达人物归属的隔离入口

`ndr.evaluation.expression_owner.ExplicitOwnerProtocol`提供独立的表达归属协议：发声、心声、引用均可携带明确人物、依据和原文引用，类型判断不会自动删除人物。引文归原文能支持的原表达者；术语或没有明确人物的引文保持未知，不能自动归给叙述者。它复用完整覆盖、实际非空引用、候选和新人物的严格编译，不因类型不同绕过证据检查。返回值保留原类型和可接受性，**不是生产QuoteLabel，禁止直接提交任务或写入书库**。正式三类表达需要通过1.1生产编译桥接；隔离提案本身不替代正式任务契约，阅读与人工更正已支持三类表达的人物保留。

`ndr.evaluation.owner_scoring.score_owners`要求调用者提供明确人物Gold及已验证的可接受性。三种类型归给正确人物均计正确；类型差异应另外统计。未知、错误、未返回目标仍进入分母；没有明确人物的Gold不能根据POV补上再计分。合法引用不证明语义正确，程序编译通过不等于模型质量通过。新入口本身不加载凭据、不发送请求、不默认开启思考，也不实现生产刷新恢复。

`ndr.llm.expression_review`提供共享三类表达裁决：`snapshot`先完整编译，保留稳定人物、原kind、调用来源、匿名声明和固有可接受性；`reconcile`将三种类型的同一人物视为身份一致，但不改写选中提案的类型。分歧可接受有支持依据的第三人物；两次未知可恢复；已一致答案被第三答案挑战时先待确认，`verify_payload`要求独立核查来源、完整覆盖和目标外反证，绑定任务与三份提案指纹。不确定核查仍保持待确认，人工锁优先，匿名同名不建立跨调用身份。`compile_decisions`整块重建1.1并传递完整批准表，调用方不能丢弃`acceptance_ceilings`；`review_effects`分别统计身份纠正/损害、新增未知/错误和类型纠正/损害。以上纯函数本身不启动模型或写库；正式Jobs在显式选择表达归属复核协议且复核次数大于0时调用这一裁决路径，默认任务不自动切换。接通任务不代表已测得语义收益，仍需固定条件和人工标准答案评估。

`ndr.evaluation.owner_constraints.ConstrainedOwnerProtocol`是显式可选的第二版：在消息中的 JSON Schema 写明未知人物必须使用 `insufficient` 和空人物证据，非空人物引用不能是空字符串，并区分类型判断与人物依据。它沿用完整严格编译，不自动清洗冲突字段，不给未知引用补叙述者。条件是提示契约，不表示提供方启用了强制结构输出，也不保证语义正确；调用者必须使用该版本的独立指纹，不能复用第一版缓存。正式Jobs显式选择`expression-production-1`时使用此协议；实验第一版默认和界面默认任务均未切换。

## 完整对话块的正式规划入口

长章完整原文可显式选择`range.context_policy=context-chapter-2`，正式规划器使用完整段落/连续对话块与原文边界证据。它保留旧`context-chapter-1`计划及缓存，整章可容时仍一窗；完整块和边界超预算时拒绝，不截断对白。初读不发送右侧原文，分窗不认证场景独立。实际行为见[契约](../docs/CONTRACTS.md)，离线覆盖可运行`backend/tests/unit/test_dialogue_blocks.py`和`backend/tests/integration/test_dialogue_block_jobs.py`。使用新策略做质量比较须冻结新版本，不能复用旧策略成绩或将无Gold的交付完整当准确率。

## 可选辅助诊断隔离

`ndr.llm.expression_diagnostics.compile_expression_diagnostics`是不调用模型或写库的隔离编译入口。正式`expression-production-1`任务只有显式冻结`auxiliary_protocol=expression-auxiliary-isolation-1`才使用它；界面对应`complete-blocks-isolated`及其独立复核版本。旧策略仍严格编译，不自动开启此模式。受话对象、受话证据及严格布尔`owner_depends_on_addressee`可作为可选辅助提案提供，不强制每个目标输出。程序先移出这些已声明的辅助字段，严格编译完整主归属，再独立验证辅助引用；坏辅助不会改变不依赖它的主结果。

明确依赖坏辅助的目标，以及它引用的其他目标和共享新身份所涉及的依赖闭包，保留原表达类型但转为未知人物；移除不再使用的新身份后再次完整编译。主身份、证据、场景、缺失/重复目标或未知主字段仍直接拒绝。结果包含有界诊断摘要、隔离目标和原提案指纹；原始输出仍应由调用者保存在既有受限调用归档中。使用者需保存该入口自身指纹，不能只用剥离后的主结果充当缓存依据。程序不能证明模型的依赖声明或引用在语义上正确，离线检查不代表已取得真实复核收益。
