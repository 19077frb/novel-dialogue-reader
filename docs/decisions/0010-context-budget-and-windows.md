# 0010 上下文、预算与处理窗口

日期：2026-09-28 · 状态：已采纳（T08）

## 问题

T08 要把「候选引语 + Gap」组织成可以送进模型的处理窗口，并定下会长期影响缓存与评测的三件事：
预算怎么算、证据怎么选、窗口怎么切。T09 的场景状态与 T10 的缓存/任务都以这里为地基。

## 选择

1. **预算先扣预留，正文预算单独记账**。`BudgetPolicy` 默认值取自 PLAN 7.3：
   正文 2500、重叠 200、状态 300、提示预留 900、输出预留 800（复核策略另有 6000/300/600）。
   账本（`BudgetLedger`）给**每一条片段**留一条记录，正文用量就是这些记录之和——
   「补入任何片段都计入预算」因此可以被断言而不是靠自觉。
2. **token 估算统一口径**：`context/budget.py::estimate_tokens` 是唯一实现
   （CJK 文字/标点约 1 token，其它约 1/4），适配器的 `estimate_tokens` 也改为调用它，
   并始终带 `method=heuristic-cjk`、`confidence=low`。接入真实分词器前不作为计费依据。
3. **证据保留层级**（PLAN 7.1）：目标对白 → 目标之间的 Gap（必留） → 场景状态/已锁定结果 →
   两端重叠 → 外层 Gap。除目标与内部 Gap 外都是可选的，预算不足时**按这个顺序丢**。
4. **horizon 与阅读模式**：`initial` 只用 `visible_horizon_cp` 以内的原文；
   `reread` 忽略 horizon。越过 horizon 的证据写入省略记录（`reason=beyond_visible_horizon`），
   **不把后文送进模型**；若必留片段被 horizon 挡住则告警并按 horizon 截断（宁可缺证据也不泄露后文）。
5. **窗口切分**：按「必留片段的 token 成本」贪心分组，窗口之间带少量重叠与
   `carry_last_quote_id` 接力点。**预算边界不是场景边界**：窗口只描述调用范围，
   场景状态仍由 T09 管理；章节边界不会重置窗口（跨章节照常携带 Gap）。
6. **超长单条引语**：单个目标自身超过正文预算时，给它独立窗口并把该目标标为
   `oversized_quote`（保留待定、按完整长度计费、**绝不截断后猜测**），同时在其他窗口继续处理其余目标。
7. **可回溯与依赖哈希**：每个片段都有 ID（quote_id / gap_id / node_id / `overlap:<range>` /
   `state:*`），窗口与计划的 `dependency_hash` 覆盖（原文版本、目标、证据、策略、提示版本、
   阅读模式、horizon、场景引用），任一变化都会得到不同哈希——T10 的缓存据此判断能否复用。

## 被放弃的方案

- **按固定条数（如前后各两句）取上下文**：PLAN 7.1 明确禁止；长间隔与心理描写往往是关键证据。
- **默认裁剪 Gap**：MVP 先保留完整较短 Gap 建立基线；激进压缩留到 T17，用真实对比实验决定。
- **超预算时截断目标发言**：会产生“半句话标签”，比待定更危险；改为独立窗口 + oversized 报告。
- **让 token 估算散落在各处**：两套口径必然漂移；统一到 `context/budget.py`。
- **把窗口当作场景边界**：会让长场景在预算边界处被强制切开身份；场景边界只由 BREAK 决定。
