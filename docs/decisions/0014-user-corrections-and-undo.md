# 0014 人工更正、锁定与撤销

日期：2026-09-28 · 状态：已采纳（T12）

## 问题

T09/T11 已经能自动标注并展示颜色/编号，但用户还不能改。T12 要决定：人工更正在哪里落库、
怎样与模型结果共存、撤销如何不丢历史、错误关联怎样被拒绝、以及哪些操作可能产生费用。

## 选择

1. **一次请求 = 一个事务 = 一个结果**：校验版本 → 写 `corrections`（前值/后值/期望版本/实际版本）→
   写 `annotation_history` 旧快照 → 改当前投影 → 解决待确认项 → 标下游 `stale`。
   任何一步失败整体回滚，前端拿不到半个结果。
2. **人工锁定优先**：更正后的标注 `source=USER`、`status=USER_CONFIRMED`、`user_locked=true`
   （`mark_unknown` 用 `status=UNKNOWN` 表达「确认未知」）。本轮同时修了一个真实缺陷：
   T10 的调度器**没有**把 `user_locked` 的 quote/group 传给 T09 引擎，模型结果会覆盖人工确认（违反 F14）；
   现在 `_apply_payload` 会把锁定的对白与分组 ID 传给 `apply_window`。
3. **未知不制造新人**：`mark_unknown` 不改类型、不建分组，只把归属锁成未知；非 speech 类型保持
   `assignment=null`，不污染普通人物颜色。
4. **普通对白也能改**：目标没有标注时先建立「未处理」占位标注（需要时新建场景），
   因此详情与更正接口不依赖待确认队列——满足「不能仅支持已在队列中的对白」。
5. **撤销 = 恢复快照 + 再写一条记录**：`corrections.undone_by` 指向撤销记录，
   `annotation_history` 只追加；目标版本不等于该次更正的 `applied_version` 时返回 409（F18），
   绝不盲回滚覆盖更新的修订。同一条更正不能重复撤销。
6. **下游依赖失效（stale）**：同一场景内、同一推理窗口（`dependency_hash`）或同一旧分组的标注
   被标为 `stale` + `STALE_DEPENDENCY` 待确认项；`user_locked` 的对白不动，也不硬删任何历史。
7. **跨场景关联一律拒绝**：`assign_existing` 的分组必须属于目标场景；显式多目标必须同场景；
   `SPLIT` 的桶必须来自同一个分组。误关联比少关联更糟，宁可 422。
8. **Gap 更正分三类结果**：`BREAK` 真正改变场景边界（关闭左侧、新场景重新编号）；
   `CONTINUE`/`UPDATE` 在右侧属于别的场景时合并回左侧；`UNCERTAIN` 只留在队列里。
   三者都写更正记录与历史，撤销按记录的原 `speaker_id` 还原。
9. **零模型调用**：`ndr/corrections` 不导入任何适配器；测试断言更正/撤销前后 `inference_runs` 行数不变。

## 被放弃的方案

- **直接删掉旧的标注再插入**：违反「不能通过硬删除历史实现撤销」，也无法按证据时点回看。
- **撤销时用「最新状态」回滚**：会覆盖用户在其它页面做的更新（F18 明确要求返回冲突）。
- **把人工结果写成 PROVISIONAL**：人工确认必须是 `USER_CONFIRMED` 且锁定，否则模型下次会覆盖。
- **把 `mark_unknown` 当成新建匿名分组**：违反 PLAN「未知不制造新人」。
- **允许跨场景指定分组**：会让编号（只在场景内有意义）失去含义，也会把两个场景的声音混在一起。
- **撤销 Gap BREAK 时重建场景**：会丢失原分组与成员关系的稳定 ID；改为按记录的旧分组精确还原。
- **在更正里顺带重新推理**：人工操作属于「无付费调用」（6.4）；需要重新推理时由用户显式发起任务。

## 验证

- `pytest backend/tests` → **302 passed**（T11 时 287；新增 `test_corrections.py` 9 项 +
  `test_identity_revisions.py` 6 项）。`ruff` 全绿。
- 覆盖到的门槛：并发旧版本 409 且不改数据（F18）；撤销越过新修订 409 且保留较新修改（F18）；
  模型响应晚于用户确认时锁定不被覆盖（F14，换模型名绕过缓存后真实调用适配器验证）；
  `mark_unknown` 不新建分组；跨场景误关联 422；同场景合并/拆分与撤销；历史只追加（行数断言）；
  更正与撤销都没有模型调用（`inference_runs` 行数不变）。
- 本轮修复的**真实缺陷**：调度器未传递 `user_locked` 目标，导致 F14 在任务路径上失效。
- 未验证（BLOCKED）：真实提供方下的更正后重推理效果（无凭据）；待确认队列的界面属 T13。
