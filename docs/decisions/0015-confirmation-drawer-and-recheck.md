# 0015 确认抽屉、队列与「复核 ≠ 展开原文」

日期：2026-09-28 · 状态：已采纳（T13）

## 问题

T12 把人工更正的接口做完了，但用户还得手写 API 才能确认。T13 要把「确认」变成不用写代码的日常操作，
同时守住两条容易走偏的边界：展开原文不能变成隐式付费调用；队列清空不能被当成「全部识别正确」。

## 选择

1. **一个抽屉 = 两个入口**：阅读页点击任意引语（着色的标注或未处理的候选虚线）与队列项「查看并确认」
   打开**同一个** `QuoteDetailDrawer`。未处理的对白也能确认（T12 的接口本来就允许），
   所以「普通对白入口」不依赖队列里有没有它。
2. **共享 CorrectionForm**：四种动作（指定已有/新建/改类型/锁定未知）在阅读页与队列页完全一致，
   表单把 `expected_version` 与 `scene_version` 一起提交，冲突时由服务端返回 409。
3. **展开原文 ≠ 模型复核**：「展开更多原文」只把 `context_window_cp` 从 120 → 600 → 2000 重取本地原文；
   局部复核是折叠区里的独立按钮，必须先选模型配置与预算，再创建 `RECHECK` 任务并显示任务面板。
   为此本轮补上了 `POST /api/quotes/{id}/recheck`（范围取当前场景，其次章节），
   让 T13 的「复核」是真实操作而不是占位按钮。
4. **队列清空 ≠ 全部正确**：`/review` 明确写出这一点并显示 `counts`（按状态/原因）；
   空结果也有同样的说明，避免把「筛出来是空的」当成整本已确认。
5. **场景边界只走 Gap 接口**：Gap 项在队列里就地展开 `GapDecisionControls`（CONTINUE/UPDATE/BREAK/UNCERTAIN），
   不复用说话人确认表单（DEVELOPMENT.md 6.3）。
6. **冲突不静默**：409 时提示「已被其它操作更新」并刷新抽屉与队列，用户看到的是最新状态而不是旧结论。
7. **更正后同步**：成功后失效 `review-items` / `quote-detail` / `annotations`，阅读页颜色、图例、
   待确认数量与队列同时更新（门槛要求）。
8. **权威计数**：受影响条数与下游 stale 条数直接取响应字段，前端不自己算。

## 被放弃的方案

- **只让队列项能确认**：违反「不能仅支持已在队列中的对白」；未处理对白也必须能确认。
- **「展开原文」顺带调用模型**：会让一次点击变成付费操作，违反 6.4。
- **复核按钮先放在 T14**：会让 T13 的门槛「展开原文与模型复核是不同操作」无法验证；
  实现一个只有提示的占位按钮等于伪造能力。
- **队列为空时显示「全部确认」**：把「没有问题项」误当成「识别正确」，是明确禁止的暗示。
- **前端自己合并/拆分分组**：合并/拆分必须走 T12 的场景级修订接口，否则历史与 stale 依赖会丢。

## 验证

- 组件测试：`CorrectionForm` 5 项、`QuoteDetailDrawer` 5 项、`ReviewPage` 4 项；前端 `vitest` 总 **55 passed**。
- E2E：`frontend/e2e/review.spec.ts` 3 项（真实后端 + 真实 Chromium + 确定性 FakeProvider，不访问网络）：
  1. 阅读页入口：标记待确认 → 锁定未知（`UNKNOWN`）→ 撤销（回到 `ACCEPTED`），阅读页仍然着色；
  2. 待定入口：队列按原因过滤 → 打开抽屉 → 跳过（延后）→ 在「已跳过」里找回；
     并验证**未处理章节的空候选**只能新建说话人；
  3. 旧版本 409：绕过界面改掉标注后，抽屉提交旧版本得到冲突提示并刷新。
- 全量 E2E：**15 passed**（原 12 + 3）。
- 本轮修复的**真实缺陷**：`GET /api/quotes/{id}` 把 `scene` 以 dict 塞进 Pydantic 模型字段，
  触发 `PydanticSerializationUnexpectedValue` 警告（改为构造 `SceneRefOut`）。
- 未验证（BLOCKED）：真实提供方的复核效果（无凭据，属 T16）；T14 的暂停/预算恢复流程。

## 迁移与回滚

不新增迁移。回滚 = 删除 `ReviewPage` / `QuoteDetailDrawer` / `CorrectionForm` / `QuoteContext` /
`RecheckPanel` / `GapDecisionControls` 与 `api/review.ts`，并把 `/books/:id/review` 从路由里移除；
后端 `POST /api/quotes/{id}/recheck` 可独立保留（T14 会用到）。
